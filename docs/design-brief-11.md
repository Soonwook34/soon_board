## 0. 무엇을 만드는 중인가 (30초 요약)

**soon-board** — F1 세션을 **다시 보기(리플레이)** 하는 개인용 대시보드다. 라이브 중계가 아니라, 이미 끝난 세션의 데이터를 처음부터 재생하며 그 시점의 순위·랩타임·트랙 위치를 본다.

- 데이터 출처는 **OpenF1 API** (비공식 커뮤니티 API, 무료).
- 화면 구성: 허브(세션 탐색) → 세션 대시보드(타이밍 보드 + 우측 레일) → 드라이버 상세 패널 / Track Map 뷰 / Compare 뷰.
- 화면 최하단에 **리플레이 트랜스포트**(재생·일시정지·배속·시킹 바)가 상주한다. 이게 이 서비스의 중심 조작계다.

### 절대 규칙 — R21 "커서 시점 원칙"

> **화면의 모든 위젯은 재생 커서(playhead) 시점의 상태만 보여준다. 커서 이후에 일어난 일은 어떤 형태로도 보이지 않는다.**

리플레이니까 결과를 이미 아는 사람도 있지만, **모르는 사람이 스포일러 없이 볼 수 있어야 한다.** 지금까지 62건의 수정 중 절반이 이 규칙 위반을 잡는 것이었다. 새 기능을 넣을 때도 이 규칙이 최우선이다.

### 건드리지 말 것

- R1~R62로 이미 확정된 동작 전반 (트랜스포트, 스포일러 게이트, 세션 변형, 색 규칙 등).
- 세션 전체 값을 가리키는 보라색은 옳다 — 대시보드 `FASTEST LAP` 카드, 연습 필드베스트 칩, 맵 최속 링, 리더보드 `FL` 배지.
- 색 의미 체계: **보라 `#B663E6` = 세션 전체 최고 / 초록 `#43C86B` = 개인 최고 / 노랑 `#D2B24E` = 그 외 / 회색 = 데이터 없음.**

# 2. 결함 수정 3건

## R63. 리더보드와 패널의 `LAST`가 커서를 무시한다 [필수]

**증상 (실측, 커서 45.5% = 랩 20):** 패널 랩 히스토리·키 모먼트 마커·Race Control·`FASTEST LAP` 카드·`FL` 배지는 전부 커서에서 정확히 잘리는데, **패스티스트 랩 시간 `1:46.812`가 두 곳에 그대로 남아 있다.**

1. 리더보드 VER 행의 `LAST LAP` 열 = `1:46.812` (보라)
2. 드라이버 패널 `LAST` 스탯 카드 = `1:46.812` (보라)

그리고 같은 패널의 랩 히스토리 최상단 완료 랩은 L20 = `1:46.612`다. **한 카드 안에서 `LAST`가 두 값이다.**

**원인:** 두 곳 모두 정적 `raceRows()`의 `row[3]`을 그대로 쓰고, 색이 `r[0]==='VER' ? '#B663E6'` / `t==='VER' ? SCc.p`로 하드코딩돼 있다. 앞선 수정에서 만든 `flSeen()` 게이팅 목록에 이 둘이 빠졌다.

**지시**
- `LAST`를 **커서 시점의 마지막 완료 랩**에서 파생하라. 패널은 이미 그 값을 갖고 있다 (랩 히스토리의 최상단 완료 행).
- 보라색은 **`flSeen()`이고 그 드라이버가 세션 최고 보유자일 때만.**

**수용 기준**
- 커서 45.5%에서 화면 어디에도 `1:46.812`가 없다 (랩 4의 우연한 동일값은 예외).
- 패널 `LAST`와 랩 히스토리 최상단 완료 랩이 **항상** 같은 값이다.

## R64. 세션 최고 보유자의 랩타임이 선언된 패스티스트 랩보다 빠르다 [필수]

**증상:** 직전 수정으로 VER 패널 L26이 `1:46.812`(= 선언된 패스티스트 랩)가 됐는데, **같은 표에 그보다 빠른 랩이 4종 있다** — `1:46.412` · `1:46.512` · `1:46.612` · `1:46.712`. 결과가 세 가지로 어긋난다:

1. **한 패널에 보라가 2행** — L26(세션 최고)과 L9(개인 최고 `1:46.412`, `bestColor`가 보라라서). 앞선 R42·R46이 없앤 바로 그 상태다.
2. 패널 `Lap Trend`의 `BEST`는 `1:46.412`인데 대시보드 `FASTEST LAP` 카드는 `1:46.812` — 여전히 두 값.
3. **Compare 카드·Compare 차트 축·스파크라인은 아직 `1:45.712`** (교정 이전 값). `genLaps(t)`를 인자 없이 부르는 경로가 3곳 남아 있다.

**지시** — 보정을 **`genLaps` 안으로** 옮겨라.
- 그 드라이버가 세션 최고 보유자면(레이스 세션 + `tla === FASTEST().tla`) `flSec = lapSec(FASTEST().time)`을 쓰고,
- **나머지 랩에 `flSec + 0.05` 하한을 걸어라.**
- 그러면 호출자 네 곳(패널·Compare 카드·Compare 차트·`trendFor`)이 자동으로 같은 값을 쓴다.

**수용 기준**
- VER 패널에 보라가 **1행(L26)**뿐이다.
- 패널 `BEST` · `FASTEST LAP` 카드 · Compare 카드 `BEST` · RC 메시지가 **모두 `1:46.812`**다.
- 화면 어디에도 `1:45.712`가 없다.

## R65. 기록 없는 드라이버가 최종 순위대로 정렬되고 순번까지 붙는다 [권장]

**증상:** 퀄리 커서 0%에서 타임은 전부 `—`인데 보드가 `P1 PIA · P2 VER · P3 NOR · P4 HAM …` **최종 Q1 순서 그대로** 서 있고 순번도 1~20이 찍혀 있다. 아직 아무도 안 달렸는데 결과 순서가 보인다. `Q3` 탭으로 점프한 직후(타임 0개)도 `P1 PIA`부터다.

**원인:** `qBoardOrder`가 `확정 그룹 + 미확정 그룹`을 잇는데, 미확정 그룹의 내부 순서가 최종 순위(`qPools().order`)다.

**지시**
- 기록 없는 드라이버는 **중립 기준으로 정렬**하라 (카 넘버 오름차순 권장).
- **순번 칸은 `—`**로 둬라. 번호는 기록이 확정된 드라이버만 1위부터 받는다.

**수용 기준**
- 퀄리 0%에서 P 열이 전부 `—`이고, 행 순서가 최종 순위와 다르다.
- Q1 50%에서 상위 8행만 번호가 있고 나머지는 `—`다.

# 3. 신규 기능 2건

## R66. 퀄리 푸시랩 미니섹터 갭 패널 [필수 · 신규]

### 무엇을

퀄리에서 어떤 드라이버가 **푸시랩(계측 랩)을 도는 중**일 때, **미니섹터를 하나씩 지날 때마다 그 시점까지 세션 최속 랩과 얼마나 차이나는지**를 보여준다. F1 TV/방송의 온보드 그래픽이 하는 일이다 — 세그먼트 색 띠 + `GAP TO FASTEST` 숫자 + 섹터별 시간.

지금 시안의 퀄리 포커스 카드에는 최종 랩타임·섹터 3개·미니섹터 띠가 있지만 **"지금 도는 중인 랩이 최속 대비 어떤가"를 보여주는 요소가 없다.**

### API로 되는가 — 부분적으로 된다. 아래 구분이 이 지시의 핵심이다

전부 실제 API를 호출해 확인했다 (2026 벨기에 GP 퀄리, 269랩).

| 요소 | 가능성 | 근거 |
|---|---|---|
| **미니섹터 색 띠** (28칸: 보라/초록/노랑) | ✅ **정확** | `laps.segments_sector_1/2/3` 배열이 색 코드를 그대로 준다. 스파는 **8+12+8 = 28칸**, 예선 랩의 86%가 완전히 채워짐 |
| **섹터 3개 시간과 색** | ✅ **정확 (ms)** | `laps.duration_sector_1/2/3` |
| 미니섹터 경계의 트랙 위치 | ✅ 확정 | 서킷 지오메트리 데이터에 미니섹터 경계 인덱스가 있고, **8번째 = 섹터1 끝 / 20번째 = 섹터2 끝**임을 실측 검증했다 |
| **미니섹터 단위 갭 숫자** | ⚠️ **파생 가능하나 오차 ±0.02초** | 차량 위치(3.7 Hz)를 트랙에 투영해 계산. 실측 오차: 섹터1 지점 **+0.019초**, 섹터2 지점 **+0.017초** |
| 방송의 3자리 숫자 (`-0.087`) | ❌ 재현 불가 | 표본 간격 270 ms의 한계. 미니섹터 단위로 물리적으로 불가능한 흔들림이 관측된다 (MS11 +0.178 → MS12 **+0.464** → MS13 +0.449) |

**결론: 색 띠와 섹터 시간은 정확하고, 갭 숫자는 근사다.** 그래서 화면에서 이 둘을 **다르게 표기**해야 한다.

### 지시

**(1) 퀄리 포커스 카드에 `GAP TO FASTEST` 블록을 추가한다.**

- 위치: 포커스 카드 안, 랩타임 바로 아래.
- 큰 숫자 하나 — **소수 2자리** (`-0.09` / `+0.24`). **3자리로 쓰지 마라.**
- 부호와 색: 음수(더 빠름) **초록 `#43C86B`**, 양수 **노랑 `#D2B24E`**, 0.005 이내는 회색 `—`.
- 라벨: `GAP TO FASTEST` (작은 대문자, `var(--labels-tertiary)`).
- 비교 대상은 **커서 시점까지의 세션 최속 랩**이다 (R21 — 세션 최종 최속이 아니다). 아직 최속 랩이 없으면 블록 전체를 `—`로.

**(2) 정확한 값과 근사값을 시각적으로 구분한다.**

- **섹터 경계 3곳**(S1 끝 / S2 끝 / 랩 완료)에서의 갭은 정확하다 → 숫자를 **굵게(font-weight 800)**, 그대로 표기.
- **그 사이 미니섹터 구간**의 갭은 근사다 → 숫자 앞에 `~`를 붙이고 **불투명도 0.75** 또는 `var(--labels-secondary)`로 한 톤 낮춘다.
- 블록 아래 9px 회색 한 줄: `Sector splits exact · between splits estimated`

**(3) 미니섹터 진행 띠 (첨부한 방송 그래픽의 그 요소).**

- 28칸 (또는 서킷별 실제 개수) 가로 배치, 칸 사이 1px 간격, 높이 6px, 라운드 1px.
- 색: 보라 `#B663E6`(오버롤 베스트) / 초록 `#43C86B`(개인 베스트) / 노랑 `#D2B24E`(그보다 느림) / 핏레인은 회색 `var(--labels-quaternary)`.
- **아직 지나지 않은 칸은 빈 칸** — `var(--labels-quinary)` 배경, 테두리 없음. 커서가 진행하며 왼쪽부터 채워진다.
- 섹터 경계(8번째·20번째 칸 뒤)에 **2px 간격**을 더 줘서 S1/S2/S3가 눈으로 갈리게. 그 아래 `S1` `S2` `S3` 라벨 (8px, `var(--labels-tertiary)`).

**(4) 섹터 3개 시간 표시.**

- `SECTOR 1 / 2 / 3` + 시간을 세로로 나열 (첨부 사진 우측처럼).
- 색은 기존 규칙: 세션 최고 섹터면 보라, 개인 최고면 초록, 그 외 기본색. 아직 안 지난 섹터는 `—`.

**(5) 이 블록은 "푸시랩 중"일 때만 보인다.**

- 아웃랩·인랩·핏레인 대기 중에는 블록 전체를 숨기고 그 자리에 한 줄: `Out lap — no gap` (또는 `In pits`).
- 목업에서는 포커스 드라이버가 푸시랩 중인 상태를 기본으로 보여주고, 아웃랩 상태도 한 번 볼 수 있게 해라.

### 수용 기준

- 퀄리 화면에서 포커스 드라이버의 `GAP TO FASTEST`가 **2자리**로 보이고, 섹터 경계에서는 굵게·그 사이에는 `~` + 흐리게 표기된다.
- 미니섹터 띠가 28칸이고, **커서 이후 칸은 비어 있다.**
- 커서를 뒤로 되감으면 채워진 칸이 줄어든다.
- 커서 0%(아무도 랩을 안 낸 시점)에서 블록 전체가 `—`다.
- 아웃랩 상태에서 블록이 숨고 `Out lap — no gap`이 보인다.

## R67. 트랙 맵 지오메트리 오버레이 [필수 · 신규]

### 무엇을

Track Map 뷰에 트랙의 구조 정보를 겹쳐 본다 — **타이밍 섹터 구분 / 마셜 섹터 / 코너 번호 / DRS zone**.

### API로 되는가 — 4개 중 3개는 되고, 2026 DRS는 안 된다

서킷 지오메트리 데이터(OpenF1이 `circuit_info_url` 필드로 직접 가리키는 외부 JSON)와 OpenF1 데이터를 실제로 대조해 확인했다. **트랙 아웃라인 좌표계가 차량 위치 좌표계와 완전히 동일해서** 변환 없이 겹칠 수 있다 (실측: x −4338…8313 vs −4341…8316).

| 오버레이 | 판정 | 근거 |
|---|---|---|
| **타이밍 섹터 S1/S2/S3 구분** | ✅ 가능 | 미니섹터 경계 8번째·20번째가 섹터 경계임을 실측 검증 (오차 0.18초·0.07초) |
| **마셜 섹터** (스파 21개) | ✅ 가능 | 지오메트리 데이터에 21개가 있고, **`race_control.sector` 번호와 대응**한다. 2026 스파 레이스에서 섹터 지정 메시지 **81건**, 값 4~19 (전부 1~21 범위) |
| **코너 번호** (스파 19개) | ✅ 가능 | 코너별 번호·트랙 위치·랩 시작부터의 누적 거리. `TURN 14` 형태 라벨이 나온다. 단 **고유명(`Stavelot` 등)은 데이터에 없다** |
| **DRS zone + 디텍션 포인트 (2023~2025)** | ✅ 도출 가능 | `car_data.drs` 전이(`8` = 디텍션 통과, `≥10` = 개방)를 차량 위치와 맞춰 구간을 산출. 실측: 2024 145건·2025 254건 / 디텍션 344건. 이 프로젝트의 다른 브랜치에 **이미 구현·검증된 산출 스크립트와 결과 파일이 있다** |
| **DRS zone (2026)** | ❌ **불가** | 2026 규정에서 DRS가 폐지됐다. `car_data.drs`가 **459/459 전부 null**이고 `race_control?category=Drs`는 **404** |
| **SLM zone (2026)** | ⚠️ **구역은 실재하나 데이터가 없다** → **R70에서 별도로 다룬다** | FIA가 서킷마다 액티베이션 존을 지정한다(멜버른 5곳·스파 5곳). 단 어떤 API도 좌표를 주지 않아 **수동 큐레이션**이 필요하다 |

**2026 세션에서 `DRS` 토글이 비활성인 건 맞지만, 그 자리를 `SLM`이 대신한다** — R70 참조.

### 지시

**(1) 오버레이는 전부 R69의 설정창에서 켜고 끈다.** 맵 헤더에 토글을 흩어 놓지 마라 — 항목이 늘어나므로 창구를 하나로 둔다. 기본값은 **`Sectors` 켜짐 / 나머지 꺼짐.**

**(2) `Sectors` — 타이밍 섹터 구분.**

- 트랙 폴리라인을 3구간으로 나눠 **서로 다른 밝기의 같은 색조**로 그린다 (색을 3개 쓰지 말고 명도만 달리 — 트랙이 알록달록해지면 차량 마커가 안 보인다).
- 경계 2곳에 트랙과 수직인 짧은 흰 선(길이 10px, 1.5px) + `S1`/`S2`/`S3` 라벨 (8px, `var(--labels-tertiary)`).

**(3) `Marshal` — 마셜 섹터.**

- 21개 구간 경계에 트랙 바깥쪽으로 작은 tick(4px) + 번호 (7px, `var(--labels-quaternary)`).
- **Race Control이 특정 섹터에 깃발을 냈고 그게 커서 시점에 유효하면, 그 구간만 해당 깃발 색으로 굵게 강조한다** (옐로 `#D2B24E` / 더블 옐로는 같은 색 + 점선). 이게 이 오버레이의 진짜 값이다 — "어디서 무슨 일이 났는지"가 맵에 보인다.
- 강조된 구간에 툴팁: `Sector 15 · Yellow flag` 형태.

**(4) `Corners` — 코너 번호.**

- 코너 위치에 작은 점(2px, `var(--labels-quaternary)`) + **숫자만** (7px). `Turn`도 `T`도 붙이지 말고 `14`처럼 숫자 하나만 쓴다. 고유명(`Stavelot` 등)은 **데이터에 없으니** 쓰지 마라.
- 19개가 다 붙으면 복잡하니, 겹치는 라벨은 생략하는 규칙을 둬라 (예: 서로 12px 이내면 하나만).

**(5) `DRS` — DRS zone (2023~2025 세션만).**

- 액티베이션 구간: 트랙 stroke를 **2배 두께 + 청록색** (`#3FB8C8` 계열)으로 덮고, 구간 시작점에 작은 `DRS ▶` 화살표.
- 디텍션 포인트: 트랙 위 작은 마름모 또는 짧은 수직선 + `DET` 라벨 (7px).
- 목업에서는 스파의 zone 2개 정도를 임의 위치에 넣어 표시 규칙만 확정하면 된다 (실좌표는 구현 시 계산).
- **2026 세션에서는 이 항목이 설정창에서 비활성**이고, 대신 `SLM`이 활성이다 (R70).

**(6) 범례.**

- 오버레이가 하나라도 켜져 있으면 맵 하단 범례에 해당 항목만 추가한다 (`▬ DRS zone` · `◆ Detection` · `▮ Marshal sector` 등). 꺼진 항목은 범례에도 없어야 한다.

### 수용 기준

- 설정창에서 각 항목을 켜고 끌 때 해당 오버레이만 나타난다.
- 커서 시점에 유효한 섹터 깃발이 있으면 `Marshal` 오버레이에서 그 구간만 강조된다. **커서 이후의 깃발은 강조되지 않는다 (R21).**
- **코너 라벨이 숫자만이다** (`Turn 14`·`T14` 아님).
- 오버레이를 다 끄면 맵이 지금과 동일하게 보인다 (회귀 없음).

## R68. 맵에 미니섹터 색 칠하기 + 포커스 드라이버 강조 [필수 · 신규]

### 무엇을

퀄리에서 드라이버 하나를 눌러 집중해서 볼 때, **트랙 맵 자체를 그 드라이버의 미니섹터 색으로 칠한다.** R66의 색 띠를 트랙 모양 위에 그리는 것이다 — 어느 코너에서 시간을 잃었는지가 위치와 함께 보인다. 동시에 **그 드라이버의 마커를 강조**한다.

### 가능한가 — ✅ 가능하다. R66과 완전히 같은 데이터다

- 미니섹터 **색**은 `laps.segments_sector_*`에 이미 있다 (스파 8+12+8=28칸).
- 미니섹터 **경계 위치**는 서킷 지오메트리의 미니섹터 인덱스로 확정된다 — 트랙 폴리라인(스파 1005점)을 그 인덱스로 자르면 각 미니섹터의 트랙 조각이 그대로 나온다. **8번째 = 섹터1 끝 / 20번째 = 섹터2 끝**임을 실측 검증했다.
- 즉 **새 데이터가 필요 없다.** R66의 띠를 펴서 트랙 모양에 감는 것뿐이다.
- ⚠️ 인덱스 개수(27)와 `segments_*` 합계(28)가 **1개 어긋난다** — 섹터 3에서 모자란다. 목업에서는 개수를 서킷 데이터에서 받는 것으로 두고, **칸 수가 어긋나도 렌더가 깨지지 않게** 설계해라 (남는 칸은 마지막 조각에 합치거나 무시).

### 지시

**(1) 미니섹터 색칠은 포커스 드라이버가 있을 때만 켜진다.**

- 조건: 퀄리(또는 연습) + 특정 드라이버가 선택된 상태.
- 레이스에서는 기본 꺼짐 — 레이스 랩의 미니섹터 데이터는 신뢰도가 낮다. 설정창에서 켤 수는 있게 두고, 기본값만 꺼둬라.

**(2) 트랙을 미니섹터 조각으로 칠한다.**

- 각 조각을 그 드라이버의 **현재(=커서 시점) 랩** 미니섹터 색으로: 보라 `#B663E6` / 초록 `#43C86B` / 노랑 `#D2B24E` / 핏레인 회색.
- **커서가 아직 지나지 않은 조각은 칠하지 않는다** — 기본 트랙 색으로 남긴다 (R21). 커서가 진행하며 트랙이 앞에서부터 물들어간다.
- 트랙 stroke를 **1.5배 두께**로 하고 색을 얹는다. 차량 마커가 묻히지 않게 **불투명도 0.85** 정도로.
- 조각 경계에 1px 간격을 둬서 칸이 구분되게.

**(3) 포커스 드라이버 마커 강조.**

- 포커스 드라이버 마커: 반지름 확대(기존 followed 수준) + 팀색 링 + 라벨 항상 표시.
- **나머지 드라이버 마커는 불투명도 0.25로 낮춘다** (지우지 말고 흐리게 — 트랙 위 다른 차의 위치도 맥락이다).
- 설정창에 **`Focus only`** 옵션을 둬서, 켜면 나머지 마커를 **완전히 숨긴다.** 사용자가 둘 중 하나를 고를 수 있게.

**(4) R66의 띠와 맵이 같은 상태를 보여야 한다.**

- 같은 랩·같은 커서 기준이므로, 띠에서 채워진 칸 수와 맵에서 칠해진 조각 수가 **항상 같아야 한다.**

### 수용 기준

- 퀄리에서 드라이버를 선택하면 맵 트랙이 그 드라이버의 미니섹터 색으로 칠해지고, 마커가 강조되며 나머지가 흐려진다.
- **커서 이후 구간은 칠해지지 않는다.** 커서를 되감으면 칠해진 구간이 줄어든다.
- R66의 띠에서 채워진 칸 수 = 맵에서 칠해진 조각 수.
- `Focus only`를 켜면 다른 마커가 사라진다.
- 포커스를 해제하면 맵이 원래대로 돌아온다 (회귀 없음).

## R69. 설정창 [필수 · 신규]

### 무엇을

오버레이·라벨·표시 옵션을 한곳에서 켜고 끄는 **설정 패널**. 지금은 이런 것들이 화면 곳곳에 흩어져 있거나(맵 `Labels` 버튼, 랩 히스토리 헤더의 숨은 `ST/I1/I2` 클릭) 아예 없다.

### 지시

**(1) 진입 지점.**

- 앱 헤더 우측(테마 토글 옆)에 톱니 아이콘 버튼. 클릭하면 **우측에서 슬라이드 인하는 패널**(폭 280~320px) 또는 팝오버.
- 닫기 버튼 + 바깥 클릭으로 닫기.

**(2) 그룹과 항목.** 아래를 그룹 헤더(9px 대문자 `var(--labels-tertiary)`)로 나눠 배치한다.

**`TRACK MAP`**
| 항목 | 형태 | 기본값 |
|---|---|---|
| Timing sectors (R67) | 스위치 | **켜짐** |
| Marshal sectors (R67) | 스위치 | 꺼짐 |
| Corner numbers (R67) | 스위치 | 꺼짐 |
| DRS zones (R67) | 스위치 | 꺼짐 · **2026 세션에서 비활성** |
| Straight mode zones (R70) | 스위치 | 꺼짐 · **2025 이전 세션에서 비활성** |
| Mini-sector colours (R68) | 스위치 | 퀄리·연습 켜짐 / 레이스 꺼짐 |
| Focus only (R68) | 스위치 | 꺼짐 |
| Marker label | **3분기 세그먼트: `Off` / `TLA` / `Number`** | `TLA` |
| Pit lane | 스위치 | 켜짐 |

- **`Marker label`이 사용자가 요청한 항목이다** — 마커에 `NOR` 대신 차량 번호 `1`을 띄우는 선택지. 기존 `mapLabels`(켜짐/꺼짐)를 이 3분기로 **대체**해라. 맵 툴바의 기존 `Labels` 버튼은 없애고 여기로 옮긴다.

**`TIMING`**
| 항목 | 형태 | 기본값 |
|---|---|---|
| Speed column | 세그먼트 `ST` / `I1` / `I2` | `ST` |
| Lap history rows | 세그먼트 `5` / `10` / `All` | `5` |

- `Speed column`은 지금 랩 히스토리 헤더를 클릭해야 순환하는 숨은 기능이다. 헤더 클릭은 그대로 두고 설정창과 **양방향 동기**시켜라.

**`REPLAY`**
| 항목 | 형태 | 기본값 |
|---|---|---|
| Jump step | 세그먼트 `10s` / `30s` / `60s` | `30s` |
| Default speed | 세그먼트 `½×` `1×` `2×` `4×` `8×` | `2×` |
| Keyboard shortcuts | 스위치 | 켜짐 |

- `Jump step`을 바꾸면 트랜스포트의 점프 버튼 숫자 라벨(`30`)과 툴팁(`Back 30 seconds`)이 **따라 바뀌어야 한다.**

**`SPOILERS`**
| 항목 | 형태 | 기본값 |
|---|---|---|
| Hide results until played | 스위치 | 켜짐 |

- 기존 스포일러 게이트(히어로 블러 · `Show result` · OFFICIAL 확인 모달)를 통째로 끄는 스위치. **끄면 게이트가 전부 사라진다.**

**`APPEARANCE`**
| 항목 | 형태 | 기본값 |
|---|---|---|
| Theme | 세그먼트 `Dark` / `Light` | `Dark` |

- 기존 헤더의 테마 버튼과 **양방향 동기.**

**(3) 비활성 항목 처리.**

- 세션 종류·연도 때문에 쓸 수 없는 항목은 **행을 지우지 말고 disabled**로 두고, 오른쪽에 이유를 9px 회색으로 한 줄 적어라.
  - `DRS zones` → 2026 세션에서 `Not in 2026 — DRS removed`
  - `Straight mode zones` → 2025 이전 세션에서 `2026 onwards only`
  - `Mini-sector colours` → 레이스에서 `Unreliable in races` (꺼짐이 기본이지만 켤 수는 있음)
- 이 disabled 상태를 목업에서 **반드시 한 번 보여줘라** (2026 세션 하나, 2024 세션 하나).

**(4) 하단에 `Reset to defaults` 텍스트 버튼** (10px, `var(--accent)`).

### 수용 기준

- 헤더 톱니 → 설정 패널이 열리고, 5개 그룹이 위 순서로 보인다.
- `Marker label`을 `Number`로 바꾸면 맵 마커 라벨이 `NOR` → `1`로 바뀐다.
- `Jump step`을 `10s`로 바꾸면 트랜스포트 버튼 라벨이 `10`, 툴팁이 `Back 10 seconds`로 바뀐다.
- `Hide results until played`를 끄면 히어로 블러와 `Show result`가 사라진다.
- 2026 세션에서 `DRS zones`가, 2024 세션에서 `Straight mode zones`가 각각 disabled + 이유 문구와 함께 보인다.
- 맵 툴바에 기존 `Labels` 버튼이 **남아 있지 않다** (설정창으로 이동 완료).

## R70. SLM(스트레이트 모드) zone + 오버테이크 모드 오버레이 [필수 · 신규]

### 무엇을

2026 세션의 트랙 맵에 **스트레이트 모드 액티베이션 존**과 **오버테이크 모드 디텍션/액티베이션 포인트**를 표시한다. 2023~2025의 DRS zone 오버레이(R67-5)와 같은 자리를 차지하는, 연도에 따른 대체물이다.

### 가능한가 — 존은 실재하고, 표시할 수 있다. 단 좌표는 수동 큐레이션이다

| 요소 | 판정 | 근거 |
|---|---|---|
| **SLM 액티베이션 존이 존재하는가** | ✅ **존재한다** | FIA가 서킷마다 지정한다. 근접 조건 없이 **전 드라이버가 쓸 수 있는 미리 지정된 구간.** 멜버른 5곳, **스파 5곳** 공표 |
| 존 좌표를 API에서 받을 수 있는가 | ❌ **불가** | 어떤 API·공개 데이터셋도 제공하지 않는다. 출처는 이벤트별 FIA 레이스 디렉터 노트(PDF)와 F1 공식 서킷 맵 그래픽 |
| **오버테이크 모드 디텍션/액티베이션 포인트** | ✅ 존재 (각 1개) | 스파: 디텍션 = 버스스톱(T19) 앞 / 액티베이션 = S/F 라인. 멜버른: 디텍션 = 마지막 직전 코너 뒤 / 액티베이션 = 마지막 코너 앞 |
| **오버테이크 모드 허용 여부(세션 상태)** | ✅ **API에 있다** | `race_control`에 **`OVERTAKE ENABLED` / `OVERTAKE DISABLED`** (2026 완료 레이스 13개 중 **11개에서 관측**, 문구는 이 두 종뿐). 2026 스파 실측: `DISABLED` → 세이프티카 해제 13:13:50 → **`ENABLED` 13:16:13** |
| 차량별 모드 사용 여부 | ❌ 불가 | `car_data`에 2026용 신규 필드가 없다 (필드 목록이 2024와 동일) |

**정리: 구간은 정적으로(수동 큐레이션) 그리고, "지금 쓸 수 있는 상태인가"는 API로 커서 연동한다. 누가 쓰고 있는지는 알 수 없다.**

### 참고 — 스파 2026의 실제 5개 존

목업에 넣을 값이다. 정확한 좌표가 아니라 코너 기준 서술이므로 **대략 위치로만** 쓴다.

1. 피트 스트레이트 — T20 출구 → T1 (라 소스)
2. 오 루즈 진입 — T1 → T2
3. 켐멜 스트레이트 — T4 → T5 (스피드트랩 포함)
4. 블랑시몽 구간 — 섹터 3, T18까지
5. (5번째 존 — 목업에서는 임의 위치)

오버테이크 모드: 디텍션 = T19(버스스톱) 앞 · 액티베이션 = S/F 라인.

### 지시

**(1) `Straight mode zones` 오버레이 (설정창 항목, 2026+ 세션만 활성).**

- 액티베이션 존: 트랙 stroke를 **2배 두께 + 밝은 파랑** (`#3E8FDB` 계열)으로 덮는다. DRS의 청록(`#3FB8C8`)과 **구분되는 색**을 써라 — 연도에 따라 다른 것이 표시된다는 게 보여야 한다.
- 각 존 시작점에 작은 `SM ▶` 화살표 (7px). 존이 5개라 라벨이 빽빽하니 **번호(`1`~`5`)만** 붙이는 것도 좋다.
- 존 툴팁: `Straight mode zone 3 · Kemmel straight` 형태. 이름은 큐레이션 데이터에서 오므로 없으면 번호만.
- **점선이 아니라 실선 굵기로.** FIA 공식 맵은 점선을 쓰지만, 여기서는 트랙 자체가 이미 얇은 선이라 점선이면 안 읽힌다.

**(2) 오버테이크 모드 포인트.**

- 디텍션 포인트: 트랙 위 작은 마름모 + `DET` (7px, `var(--labels-tertiary)`).
- 액티베이션 포인트: 짧은 수직선 + `OVT` (7px).
- DRS 오버레이의 디텍션 표기(R67-5)와 **같은 모양**을 쓴다 — 연도만 다른 같은 개념이니까.

**(3) 허용 상태 표시 — 이게 이 오버레이의 살아있는 부분이다.**

- 커서 시점에 오버테이크 모드가 **허용 중이면** 포인트와 존을 정상 밝기로, **금지 중이면 불투명도 0.35 + 회색조**로 그린다.
- 맵 하단 또는 범례 옆에 상태 칩 하나: `OVERTAKE ENABLED` (초록 `#43C86B`) / `OVERTAKE DISABLED` (회색). **커서를 움직이면 이 칩이 바뀌어야 한다.**
- 목업에서 **두 상태를 다 볼 수 있게** 해라 (세이프티카 구간에서는 DISABLED, 재개 2랩 뒤부터 ENABLED).

**(4) 정확도에 대한 정직한 표기.**

- 존 좌표가 수동 큐레이션 근사이고 주말 중 길이가 조정될 수 있으므로, 오버레이가 켜져 있을 때 범례에 9px 회색 한 줄: `Zone positions approximate`
- 이건 지우지 마라. 데이터가 아니라 사람이 옮겨 적은 값이라는 표시다.

### 수용 기준

- 2026 세션에서 `Straight mode zones`를 켜면 존 5개 + `DET`/`OVT` 포인트가 보이고, **2024 세션에서는 이 항목이 disabled**다.
- DRS 오버레이와 SLM 오버레이의 **색이 다르다.**
- 상태 칩이 커서에 따라 `OVERTAKE ENABLED` ↔ `DISABLED`로 바뀌고, 금지 중일 때 존이 흐려진다.
- 범례에 `Zone positions approximate` 한 줄이 있다.

# 4. 작업 순서와 보고 방식

## 순서

1. **R63 · R64 · R65** — 좁은 결함 수정. 먼저 끝내라.
2. **R69 설정창** — R67·R68·R70이 전부 여기에 항목을 등록하므로 **컨테이너를 먼저** 만드는 게 낫다.
3. **R67 → R68 → R70** — 맵 오버레이 3건. R67의 미니섹터 경계 계산이 R68의 기반이고, R70은 R67-5(DRS)의 연도별 대체물이다.
4. **R66** — 퀄리 포커스 카드. R68과 같은 데이터를 쓰므로 마지막에 하면 재사용이 쉽다.

## 보고

각 항목을 **①수정함 / ②이미 충족 / ③보류(사유)** 중 하나로 보고해줘. 수용 기준 충족 여부까지 확인해서 적어줘.

특히 이 7개는 꼭 확인해줘:

1. **R63** — 커서 45.5%에서 화면 어디에도 `1:46.812`가 없는지.
2. **R64** — VER 패널에 보라가 1행뿐이고, 어디에도 `1:45.712`가 없는지.
3. **R66** — 갭 숫자가 2자리인지, 섹터 경계는 굵게·그 사이는 `~`로 구분되는지, 커서 이후 미니섹터 칸이 비어 있는지.
4. **R67** — 코너 라벨이 **숫자만**인지 (`Turn 14`·`T14` 아님).
5. **R68** — 커서 이후 트랙이 칠해지지 않는지, R66의 띠 칸 수와 맵 조각 수가 같은지.
6. **R69** — `Marker label`을 `Number`로 바꾸면 마커가 `1`로 바뀌는지, `Jump step`이 트랜스포트 라벨에 반영되는지, 맵 툴바의 기존 `Labels` 버튼이 제거됐는지.
7. **R70** — 2026에서 SLM 활성·DRS 비활성 / 2024에서 그 반대인지, 상태 칩이 커서에 따라 바뀌는지.

## 두 가지 금지 사항

**(1) 정확도 표기를 임의로 3자리로 올리지 마라.** ±0.02초가 실측 오차라서, 3자리는 없는 정밀도를 있는 것처럼 보이게 한다. 이 지시서에서 "정확"이라고 쓴 것(섹터 타임 · 미니섹터 색 · 마셜 섹터 · 코너 위치)과 "근사"라고 쓴 것(미니섹터 갭 숫자 · SLM 존 위치)의 구분이 R66·R70의 요점이다.

**(2) 커서 이후를 보여주지 마라.** 새 오버레이도 R21의 예외가 아니다 — 미니섹터 색(R68), 마셜 섹터 깃발(R67), 오버테이크 허용 상태(R70)는 모두 **커서 시점 값**이어야 한다. 최종 결과를 미리 칠하면 리플레이 내내 스포일러가 된다.
