# soon-board 디자인 수정 지시서 — API 감사 반영 (2차 브리프)

> **용도:** claude design "Claude Design Study" 프로젝트의 `SoonBoard.dc.html`에 적용할 **수정 지시**. 2026-07-24에 완성된 디자인 전체를 OpenF1 API 실측 레퍼런스와 대조 감사한 결과다.
> **이 문서 하나로 충분하다** — 각 항목에 지시·근거·수용 기준이 모두 들어 있으므로 다른 문서를 요청하지 말 것. (1차 브리프 `design-brief.md`의 C1~C10은 이미 대부분 충족 확인됨 — §5의 "유지 목록"은 건드리지 말 것.)
> 우선순위: **[필수]** 데이터가 존재하지 않아 그대로 두면 구현 불가 · **[권장]** 표시 규칙 보완 · **[선택]** 여유 시.

## 1. 구조 수정 — 화면 축 단위 [필수]

### R1. "World Feed / ON AIR" 개념 전면 재정의 (맵 화면)
- **문제:** 맵 화면의 온에어 스트립("World Feed … TV shows 4 cars. You track the other 16 →"), 마커의 온에어 할로, 스탠딩 레일의 빨간 점("On air · tap for detail"), 팔로우 카드의 ON AIR/OFF SCREEN 라벨이 전부 "지금 TV 중계 화면에 잡힌 차" 데이터를 전제한다. **OpenF1 18개 엔드포인트 어디에도 방송/월드피드 정보는 없다.**
- **지시:** "TV에 안 나오는 차를 추적한다"는 가치 제안은 유지하되 데이터 근거를 교체하라.
  - 온에어 스트립 → **배틀 스트립**: 인터벌 ≤1.0s로 묶인 배틀 그룹(이미 맵에 점선으로 존재)을 카드로 나열. "TV shows N cars" 문구 삭제.
  - 마커 할로·스탠딩 빨간 점 → 배틀 참여 차 또는 사용자가 팔로우한 차 표시로 교체.
  - ON AIR / OFF SCREEN 라벨 → 팔로우 상태(FOLLOWING) 또는 배틀 태그(IN BATTLE)로 교체.
- **수용 기준:** "World Feed", "On air", "TV" 문자열이 화면에서 사라지고, 같은 자리의 UI가 intervals·사용자 상태만으로 설명 가능할 것.

### R2. 연습(FP1–3) 세션 전용 변형 추가
- **문제:** 허브에서 FP1~FP3도 REPLAY로 진입하는데 현재 레이스 대시보드(인터벌 리더보드)로 열린다. **연습 세션에는 `intervals`가 존재하지 않는다(조회 시 404가 정상).** LAP n/n 진행 개념도 없다.
- **지시:** 퀄리 화면을 변형해 **연습 변형**을 만들어라: 베스트 랩타임 정렬 타워(갭 = 베스트랩 Δ), 컷라인·녹아웃 없음, 진행 표기는 세션 경과 시간, 드라이버별 랩 수 컬럼 추가. 우측 레일은 날씨 + 레이스컨트롤 + 베스트섹터 유지.
- **수용 기준:** 허브에서 FP 세션 진입 시 인터벌 컬럼이 있는 화면이 절대 나오지 않을 것.

## 2. 존재하지 않는 데이터 제거·대체 [필수]

| # | 위치 | 문제 | 지시 |
|---|---|---|---|
| R3 | 드라이버 패널 DNF 스탯 ("Cause: Collision damage" 등) | 리타이어 **원인 텍스트는 API에 없음** (`session_result`는 dnf 불리언만) | Cause 칸 삭제. 대신 해당 차 관련 race_control 메시지 원문(자유 텍스트)을 1~2줄 인용하는 영역으로 교체 — 없을 수도 있으므로 빈 상태 포함 |
| R4 | 퀄리 헤더 "12:20 remaining" / 세그먼트 진행바 % | **세션 시계(남은 시간)는 API에 없음.** 리플레이에선 타임스탬프 근사만 가능하고 레드플래그 중단 시 부정확 | "remaining" 카운트다운 → **경과 시간 표기**("Q2 · 10:48 elapsed")로 교체. 진행바는 데이터 타임스탬프 기반임을 전제로 유지 가능 |
| R5 | 허브 히어로 "Dry · rain expected later" | `weather`는 관측치만 제공, **예보 없음** | 히어로 요약은 관측만: "Dry · 17°C air". 예보성 문구는 race_control 원문 인용(티커의 "Rain expected within 10 minutes"는 실제 FIA 메시지라 유지 가능)일 때만 |

| R9 | "R10" 라운드 배지 | 라운드 번호 필드 없음 — 시즌 내 `date_start` 순서로 파생(테스트 제외). 디자인 변경 불요, 전제만 인지 |

| R11 | 허브 연도 토글 2023–2026 | 서비스 백필 범위는 **2024~현재**(infra 확정). 2023 세그먼트 삭제 (또는 "준비 안 됨" 비활성 상태) |

## 5. 유지 목록 — 변경 금지 (이미 올바름)

감사에서 정합 확인된 항목. 위 수정 작업 중 부수적으로 훼손하지 말 것.

- "Live · soon" 비활성 pill과 라이브 진입 차단 (C1)
- Collecting %·수집 대기 상태, 로딩 프로그레스(스피너 없음) (C2·C3)
- "+1 LAP" 랩다운 배지 분기 (C4)
- PROVISIONAL 배지·배너 (C5의 잠정 측 — R14는 확정 측 추가일 뿐)
- 국기·국적: 드라이버 국적 미표시 (C6), GP 국기는 CSS 그라디언트 자작(외부 CDN 비의존 — 유지)
- 팀 컬러 바 (C8), 텔레메트리·팀라디오 위젯 부재 (C9), 푸터 OpenF1 크레딧 (C10)
- 퀄리 "Gap = best-lap Δ · no live interval in qualifying" 명시, 컷라인·녹아웃 리스트
- 맵의 (0,0,0) 숨김 칩("N cars · no signal"), 키 모먼트 마커, 배속·스크럽 컨트롤

## 7. 3차 수정 (R28~R30) — 라이브맵 확장·허브 동선·리플레이 트랜스포트

> 사용자 요청 3건을 OpenF1 API 실측·인프라 확정 구조와 대조 검증한 결과 — **셋 다 구현 가능 판정.** 라이브맵이 서비스의 핵심 요소다(R28 최우선).

### R28. 맵 뷰를 전 세션 공통으로 — Practice·Qualifying에도 [필수]
- **검증:** 가능. `location`(3.7 Hz 좌표)은 세션 타입 무관 제공 — Spa 2026 실측: FP1 드라이버당 18,267행, 퀄리 20,031행 (레이스 32,771행). 트랙 지오메트리·좌표계도 동일. 레이스 전용인 것은 `intervals`뿐이다.
- **지시:**
  - 맵을 레이스 전용 화면에서 **세션 공통 뷰**로 승격: Practice·Qualifying 세션 헤더에도 Dashboard ↔ Map 스위치 노출 (현재 race에만 있는 viewSwitch).
  - 레이스 전용 모듈 분기: **배틀 스트립·인터벌 수치·랩다운 배지는 인터벌 기반이므로 P/Q 맵에서 제거.**
  - 퀄리 맵: 트랙 위 각 차에 **주행 상태 태그 3종 — OUT LAP / ON TRACK / IN PIT** (`laps.is_pit_out_lap`·`pit`·(0,0,0) 좌표로 판정). ⚠ "IN LAP"(핏 복귀 중) 라벨은 커서 시점에 알 수 없는 미래 정보라 금지 (R21). 스탠딩 레일은 퀄리 타워(베스트랩 정렬·컷라인) 재사용.
  - 프랙티스 맵: 트랙 위 N대/가라지 N대 칩(기존 유지) + 방금 베스트랩을 경신한 차 하이라이트. 스탠딩 레일은 프랙티스 타워 재사용.
- **수용 기준:** FP·퀄리에서 맵 진입 가능 / P·Q 맵에 인터벌 기반 요소 0개 / 상태 태그가 커서 시점까지의 데이터만으로 설명 가능.

### R29. 허브 GP 카드 — 결과 공개와 세션 선택 동선 분리 [필수]
- **문제:** 결과 스포일러 가드(R18)의 "Show result"와 카드 클릭(세션 리스트 확장)이 같은 표면에서 충돌. 구조상 호버 결과 패널이 플로팅(카드 하단 겹침, z-40)이라 확장된 세션 리스트·인접 카드의 클릭 영역을 가린다.
- **지시:**
  - **플로팅/오버레이형 결과 패널 폐지.** 호버는 카드 하이라이트만 — 호버로 어떤 결과 요소도 출현 금지.
  - 카드 클릭 = **세션 리스트 확장** 단일 의미로 고정 (확장 리스트는 스포일러 0 보장).
  - 결과 공개는 확장 영역 **내부 맨 아래의 "Show result" 행**으로: 클릭 시 그 자리에서(in-place) 포디움 3줄 + fastest lap 인라인 공개. 인라인 확장이므로 세션 행·인접 카드와 클릭 영역이 절대 겹치지 않는다.
  - 공개 상태는 GP 카드별 개별 토글(전역 아님). 히어로도 동일 패턴 — Open Race Replay 버튼과 분리된 자리의 명시 토글.
- **수용 기준:** ①호버만으로 결과 노출 0 ②Show result와 세션 행의 클릭 영역 겹침 0 (플로팅 결과 패널 부재) ③결과 공개 없이 카드→세션→리플레이 완주 가능.

### R30. 리플레이 트랜스포트 — 임의 시점 시킹·배속·일시정지 구현 가능 확정 [권장]
- **검증:** 전부 가능. 인프라 확정 구조상 리플레이는 세션 전체 청크(레이스 ~7.5 MB gz)를 클라이언트가 통째로 보유한 채 재생한다 — 시킹·배속·일시정지는 순수 로컬 연산이고, 재생 중 OpenF1 호출이 없어 rate limit·네트워크 지연과 무관. 임의 시점 점프는 타임스탬프 이진 탐색으로 즉시 되고, 점프 시 위젯 상태는 소형 스트림(position·stints·race_control 등)을 그 시점까지 집계해 재구성한다(R21 총칙 그대로, ms 단위 연산).
- **지시:** 현행 컨트롤(재생/일시정지 · ±15 s · 배속 ½/1/2/4× · 진행바 클릭 점프 · 랩 틱 · 키 모먼트)은 **확정 기능으로 유지**하고 3가지 보강:
  - ① 진행바 **드래그 시킹** + 호버 시 커서 위치의 랩/시각 툴팁 (클릭 전 목적지 확인)
  - ② 앞으로 점프는 허용(사용자 의사)하되 **점프 도착 지점이 새 "기시청 최대 지점"이 된다**는 전제로 R20 마커·음영 규칙 적용 — 도착 지점 이후 구간은 여전히 무표시
  - ③ [선택] 배속 8× 추가 — 데이터가 로컬이라 상한은 렌더 성능뿐
- **수용 기준:** 진행바 임의 지점 클릭·드래그로 즉시 해당 시점 재생 / 점프 직후 모든 위젯이 그 시점 상태(R21) / 미시청 구간 마커 무표시 유지(R20).
