# soon-board 디자인 수정 지시서 — API 감사 반영 (2차 브리프)

> **용도:** claude design "Claude Design Study" 프로젝트의 `SoonBoard.dc.html`에 적용할 **수정 지시**. 2026-07-24에 완성된 디자인 전체를 OpenF1 API 실측 레퍼런스와 대조 감사한 결과다.
> **이 문서 하나로 충분하다** — 각 항목에 지시·근거·수용 기준이 모두 들어 있으므로 다른 문서를 요청하지 말 것. (1차 브리프 `design-brief.md`의 C1~C10은 이미 대부분 충족 확인됨 — §5의 "유지 목록"은 건드리지 말 것.)
> 우선순위: **[필수]** 데이터가 존재하지 않아 그대로 두면 구현 불가 · **[권장]** 표시 규칙 보완 · **[선택]** 여유 시.

## 1. 구조 수정 — 화면 축 단위 [필수]

### R1. "World Feed / ON AIR" 개념 전면 재정의 (맵 화면)
- **문제:** 맵 화면의 온에어 스트립("World Feed … TV shows 4 cars. You track the other 16 →"), 마커의 온에어 할로, 스탠딩 레일의 빨간 점("On air · tap for detail"), 팔로우 카드의 ON AIR/OFF SCREEN 라벨이 전부 "지금 TV 중계 화면에 잡힌 차" 데이터를 전제한다. **OpenF1 18개 엔드포인트 어디에도 방송/월드피드 정보는 없다.**
- **지시:** "TV에 안 나오는 차를 추적한다"는 가치 제안은 유지하되 데이터 근거를 교체하라.
  - 온에어 스트립 → **배틀 스트립**: 인터벌 ≤1.0s로 묶인 배틀 그룹(이미 맵에 점선으로 존재)을 카드로 나열. "TV shows N cars" 문구 삭제.
  - 마커 할로·스탠딩 빨간 점 → 배틀 참여 차 또는 사용자가 팔로우한 차 표시로 교체.
  - ON AIR / OFF SCREEN 라벨 → 팔로우 상태(FOLLOWING) 또는 배틀 태그(IN BATTLE)로 교체.
- **수용 기준:** "World Feed", "On air", "TV" 문자열이 화면에서 사라지고, 같은 자리의 UI가 intervals·사용자 상태만으로 설명 가능할 것.

### R2. 연습(FP1–3) 세션 전용 변형 추가
- **문제:** 허브에서 FP1~FP3도 REPLAY로 진입하는데 현재 레이스 대시보드(인터벌 리더보드)로 열린다. **연습 세션에는 `intervals`가 존재하지 않는다(조회 시 404가 정상).** LAP n/n 진행 개념도 없다.
- **지시:** 퀄리 화면을 변형해 **연습 변형**을 만들어라: 베스트 랩타임 정렬 타워(갭 = 베스트랩 Δ), 컷라인·녹아웃 없음, 진행 표기는 세션 경과 시간, 드라이버별 랩 수 컬럼 추가. 우측 레일은 날씨 + 레이스컨트롤 + 베스트섹터 유지.
- **수용 기준:** 허브에서 FP 세션 진입 시 인터벌 컬럼이 있는 화면이 절대 나오지 않을 것.

## 2. 존재하지 않는 데이터 제거·대체 [필수]

| # | 위치 | 문제 | 지시 |
|---|---|---|---|
| R3 | 드라이버 패널 DNF 스탯 ("Cause: Collision damage" 등) | 리타이어 **원인 텍스트는 API에 없음** (`session_result`는 dnf 불리언만) | Cause 칸 삭제. 대신 해당 차 관련 race_control 메시지 원문(자유 텍스트)을 1~2줄 인용하는 영역으로 교체 — 없을 수도 있으므로 빈 상태 포함 |
| R4 | 퀄리 헤더 "12:20 remaining" / 세그먼트 진행바 % | **세션 시계(남은 시간)는 API에 없음.** 리플레이에선 타임스탬프 근사만 가능하고 레드플래그 중단 시 부정확 | "remaining" 카운트다운 → **경과 시간 표기**("Q2 · 10:48 elapsed")로 교체. 진행바는 데이터 타임스탬프 기반임을 전제로 유지 가능 |

| R9 | "R10" 라운드 배지 | 라운드 번호 필드 없음 — 시즌 내 `date_start` 순서로 파생(테스트 제외). 디자인 변경 불요, 전제만 인지 |

| R11 | 허브 연도 토글 2023–2026 | 서비스 백필 범위는 **2024~현재**(infra 확정). 2023 세그먼트 삭제 (또는 "준비 안 됨" 비활성 상태) |

## 5. 유지 목록 — 변경 금지 (이미 올바름)

감사에서 정합 확인된 항목. 위 수정 작업 중 부수적으로 훼손하지 말 것.

- "Live · soon" 비활성 pill과 라이브 진입 차단 (C1)
- Collecting %·수집 대기 상태, 로딩 프로그레스(스피너 없음) (C2·C3)
- "+1 LAP" 랩다운 배지 분기 (C4)
- PROVISIONAL 배지·배너 (C5의 잠정 측 — R14는 확정 측 추가일 뿐)
- 국기·국적: 드라이버 국적 미표시 (C6), GP 국기는 CSS 그라디언트 자작(외부 CDN 비의존 — 유지)
- 팀 컬러 바 (C8), 텔레메트리·팀라디오 위젯 부재 (C9), 푸터 OpenF1 크레딧 (C10)
- 퀄리 "Gap = best-lap Δ · no live interval in qualifying" 명시, 컷라인·녹아웃 리스트
- 맵의 (0,0,0) 숨김 칩("N cars · no signal"), 키 모먼트 마커, 배속·스크럽 컨트롤

## 7. 3차 수정 (R28~R30) — 라이브맵 확장·허브 동선·리플레이 트랜스포트

> 사용자 요청 3건을 OpenF1 API 실측·인프라 확정 구조와 대조 검증한 결과 — **셋 다 구현 가능 판정.** 라이브맵이 서비스의 핵심 요소다(R28 최우선).

### R28. 맵 뷰를 전 세션 공통으로 — Practice·Qualifying에도 [필수]
- **검증:** 가능. `location`(3.7 Hz 좌표)은 세션 타입 무관 제공 — Spa 2026 실측: FP1 드라이버당 18,267행, 퀄리 20,031행 (레이스 32,771행). 트랙 지오메트리·좌표계도 동일. 레이스 전용인 것은 `intervals`뿐이다.
- **지시:**
  - 맵을 레이스 전용 화면에서 **세션 공통 뷰**로 승격: Practice·Qualifying 세션 헤더에도 Dashboard ↔ Map 스위치 노출 (현재 race에만 있는 viewSwitch).
  - 레이스 전용 모듈 분기: **배틀 스트립·인터벌 수치·랩다운 배지는 인터벌 기반이므로 P/Q 맵에서 제거.**
  - 퀄리 맵: 트랙 위 각 차에 **주행 상태 태그 3종 — OUT LAP / ON TRACK / IN PIT** (`laps.is_pit_out_lap`·`pit`·(0,0,0) 좌표로 판정). ⚠ "IN LAP"(핏 복귀 중) 라벨은 커서 시점에 알 수 없는 미래 정보라 금지 (R21). 스탠딩 레일은 퀄리 타워(베스트랩 정렬·컷라인) 재사용.
  - 프랙티스 맵: 트랙 위 N대/가라지 N대 칩(기존 유지) + 방금 베스트랩을 경신한 차 하이라이트. 스탠딩 레일은 프랙티스 타워 재사용.
- **수용 기준:** FP·퀄리에서 맵 진입 가능 / P·Q 맵에 인터벌 기반 요소 0개 / 상태 태그가 커서 시점까지의 데이터만으로 설명 가능.

### R29. 허브 GP 카드 — 결과 공개와 세션 선택 동선 분리 [필수]
- **문제:** 결과 스포일러 가드(R18)의 "Show result"와 카드 클릭(세션 리스트 확장)이 같은 표면에서 충돌. 구조상 호버 결과 패널이 플로팅(카드 하단 겹침, z-40)이라 확장된 세션 리스트·인접 카드의 클릭 영역을 가린다.
- **지시:**
  - **플로팅/오버레이형 결과 패널 폐지.** 호버는 카드 하이라이트만 — 호버로 어떤 결과 요소도 출현 금지.
  - 카드 클릭 = **세션 리스트 확장** 단일 의미로 고정 (확장 리스트는 스포일러 0 보장).
  - 결과 공개는 확장 영역 **내부 맨 아래의 "Show result" 행**으로: 클릭 시 그 자리에서(in-place) 포디움 3줄 + fastest lap 인라인 공개. 인라인 확장이므로 세션 행·인접 카드와 클릭 영역이 절대 겹치지 않는다.
  - 공개 상태는 GP 카드별 개별 토글(전역 아님). 히어로도 동일 패턴 — Open Race Replay 버튼과 분리된 자리의 명시 토글.
- **수용 기준:** ①호버만으로 결과 노출 0 ②Show result와 세션 행의 클릭 영역 겹침 0 (플로팅 결과 패널 부재) ③결과 공개 없이 카드→세션→리플레이 완주 가능.

### R30. 리플레이 트랜스포트 — 임의 시점 시킹·배속·일시정지 구현 가능 확정 [권장]
- **검증:** 전부 가능. 인프라 확정 구조상 리플레이는 세션 전체 청크(레이스 ~7.5 MB gz)를 클라이언트가 통째로 보유한 채 재생한다 — 시킹·배속·일시정지는 순수 로컬 연산이고, 재생 중 OpenF1 호출이 없어 rate limit·네트워크 지연과 무관. 임의 시점 점프는 타임스탬프 이진 탐색으로 즉시 되고, 점프 시 위젯 상태는 소형 스트림(position·stints·race_control 등)을 그 시점까지 집계해 재구성한다(R21 총칙 그대로, ms 단위 연산).
- **지시:** 현행 컨트롤(재생/일시정지 · ±15 s · 배속 ½/1/2/4× · 진행바 클릭 점프 · 랩 틱 · 키 모먼트)은 **확정 기능으로 유지**하고 3가지 보강:
  - ① 진행바 **드래그 시킹** + 호버 시 커서 위치의 랩/시각 툴팁 (클릭 전 목적지 확인)
  - ② 앞으로 점프는 허용(사용자 의사)하되 **점프 도착 지점이 새 "기시청 최대 지점"이 된다**는 전제로 R20 마커·음영 규칙 적용 — 도착 지점 이후 구간은 여전히 무표시
  - ③ [선택] 배속 8× 추가 — 데이터가 로컬이라 상한은 렌더 성능뿐
- **수용 기준:** 진행바 임의 지점 클릭·드래그로 즉시 해당 시점 재생 / 점프 직후 모든 위젯이 그 시점 상태(R21) / 미시청 구간 마커 무표시 유지(R20).

### 9.1 데이터 정합 [필수]

### R35. 리타이어 드라이버 패널의 스틴트·핏 섹션이 빈 상태 [신규]
- **증상:** BOT(L3 리타이어) 패널의 STINT HISTORY가 **빈 회색 바**이고 요약이 `No stops ·`(뒤에 아무것도 없는 구분자)로 끝난다. PIT STOPS 섹션은 각주("Stationary time · pre-2024 sessions…")만 남고 행이 0개다. STR(L12)도 동일.
- **원인:** 스틴트/핏 구성이 **완주자 목록(타워 20행)에만 의존**한다 — 리타이어 드라이버는 그 목록에 없으니 스틴트 배열이 빈 배열로 떨어진다.
- **API 근거:** `/v1/stints`는 **분류 결과와 무관하게** `stint_number`·`lap_start`·`lap_end`·`compound`·`tyre_age_at_start`를 준다(레퍼런스 §8.7). L3에 리타이어해도 **최소 1개 스틴트(L1~L3, 스타팅 컴파운드)는 존재**한다. 즉 "데이터가 없어서 빈 것"이 아니라 **제공되는 데이터를 못 쓰고 있는 것**이다.
- **지시:**
  1. 스틴트 타임라인을 완주 여부와 무관하게 구성하고 **리타이어 랩에서 끊어라**(R34와 동일 규칙). BOT은 `L1–L3` 단일 스틴트 1개.
  2. 핏 스톱이 0회면 빈 섹션이 아니라 **명시적 빈 상태 문구**("No pit stops" 등)를 두고, 각주는 값이 있을 때만 노출.
  3. 스틴트가 1개일 때 요약 문자열의 **접미 구분자(`·`)가 남지 않도록** 할 것.
  4. **1랩 리타이어 케이스를 정의하라** — 랩이 1개면 Lap Trend 스파크라인이 선을 그릴 수 없다(점 1개). 점 하나 + 수치만, 또는 "Insufficient laps for trend" 같은 대체 표시. 1랩 사고 리타이어는 실제 레이스에서 흔하다.
- **수용 기준:** BOT 패널에 `H`(또는 스타팅 컴파운드) 스틴트 바 1개가 `L1–L3` 범위로 보이고, 축은 `Lap 1 … Lap 3`, PIT STOPS는 명시적 빈 상태. STR은 `L1–L12`.

### R36. Practice 드라이버 패널 본문이 여전히 레이스 콘텐츠 [R22 부분 반영]
- **증상:** Practice 2 · ALO 패널 **한 화면 안에 베스트랩이 두 값**이다 — 스탯 행 `BEST LAP 1:40.796`(연습 데이터) vs Lap Trend `BEST 1:49.188`(레이스 데이터). 이어서 스탯은 `LAPS 13`인데 랩 히스토리는 **L24~L28 + 진행 중 L29**, 버튼은 "Show all 28 laps", STINT HISTORY는 `1 stop · H14 → M14`에 핏 스톱 `Lap 14 · 2.41s`.
- **원인:** R22에서 **스탯 6칸만** 연습용으로 교체되고, 그 아래 본문(랩 히스토리·Lap Trend·스틴트·핏)은 레이스 생성기를 그대로 쓴다.
- **지시:** 연습 세션에서는 패널 본문 전체를 연습 데이터로 통일하라.
  - 랩 히스토리: 그 드라이버가 **연습에서 실제로 돈 랩 수**(스탯의 `LAPS` 값)만, 랩 번호도 1..N. 진행 중 랩 행은 세션이 진행 중일 때만.
  - Lap Trend의 `BEST`/`LAST`/`AVG`는 스탯 행과 **같은 소스**.
  - 스틴트: 연습은 컴파운드 교체가 핏 전략이 아니라 **런 플랜**이다 — `1 stop` 같은 레이스 어휘 대신 런(run) 단위로 표기하고, 핏 스톱 섹션은 정지 시간이 아니라 박스 진입 랩 정도로 축소하거나 감출 것.
- **수용 기준:** Practice 패널 안에서 베스트랩 값이 **한 개**이고, 랩 히스토리 최대 랩 번호 ≤ 스탯 `LAPS` 값이며, "stop"이라는 표현이 없을 것.

### R37. OFFICIAL 배너 카피가 실제 표기와 불일치 [필수]
- **증상:** 배너는 `1 time penalty · 2 cars classified as retired`인데, 같은 화면 리타이어 목록에서 **BOT은 `DSQ` / `Disqualified`**로 표시된다. 실제 집계는 리타이어 1 + 실격 1이다.
- **API 근거:** `session_result`의 `dnf`/`dns`/`dsq`는 **서로 다른 boolean**(레퍼런스 §8.14) — 하나로 뭉쳐 셀 수 없다.
- **지시:** 배너 문구를 실제 집계에서 생성하라 — `1 time penalty · 1 retired · 1 disqualified` 형태. 0인 항목은 문구에서 빼고, 셋 다 0이면 페널티 절만 남길 것.
- **수용 기준:** 배너의 각 숫자가 화면의 해당 태그(OUT / DSQ / DNS) 개수와 일치.

### R38. OFFICIAL에서 페널티가 순위에 미반영 [필수]
- **증상:** HAM 행에 `+5s` 페널티 배지가 붙었는데 **순위는 P6 그대로**이고 인터벌도 `+3.215`로 불변이다. PROVISIONAL → OFFICIAL 사이에 순서 변동이 0이다.
- **API 근거:** **최종 순위 ≠ 마지막 `position`** — 페널티 반영은 `session_result`에만 있다(레퍼런스 §주의 601, §5 "최종 결과 ≠ 마지막 position"). PROVISIONAL(라이브 타이밍 순서)과 OFFICIAL(스튜어드 확정)이 **다를 수 있다는 것이 두 상태를 나눈 이유**인데, 지금은 배지만 다르고 순서가 같아 상태 구분의 의미가 사라진다.
- **지시:** OFFICIAL 전환 시 순위를 `session_result` 기준으로 **재정렬**하고(목업에서는 페널티가 실제로 순위를 바꾸는 예시로), PROVISIONAL 대비 변동을 **▲/▼ + 칸 수**로 표시하라. 페널티로 밀린 행과 올라온 행이 둘 다 보이게 할 것.
- **수용 기준:** PROVISIONAL과 OFFICIAL의 상위 10행 순서가 최소 한 쌍 이상 다르고, 변동한 행에 방향 표시가 있을 것.

### R39. 스프린트 주말에 FP2·FP3가 노출 [필수 · 1차 브리프 §1 미준수 잔존]
- **증상:** 허브에서 스프린트 주말 GP를 펼치면 세션 칩이 `FP1 · FP2 · FP3 · Sprint Quali · Sprint · Qualifying · Race`로 나온다. 스프린트 주말도 연습 3회로 표시된다.
- **API 근거:** 실측상 스프린트 주말의 연습 세션은 **`Practice 1` 하나뿐**이다. v1부터 남아 있는 항목으로 1차 브리프 §1에서 이미 지시했으나 미반영.
- **지시:** 스프린트 주말 세션 구성을 `Practice 1 · Sprint Qualifying · Sprint · Qualifying · Race` **5개**로 하라. 일반 주말은 `Practice 1 · 2 · 3 · Qualifying · Race`로 현행 유지.
- **수용 기준:** 스프린트 주말 카드에 FP2·FP3 칩이 존재하지 않을 것.

### 9.2 표시 규칙 [권장]

### R40. 총 랩 수 분모의 게이팅 축이 잘못됐다
- **현상:** 헤더 랩 카운터 분모가 **OFFICIAL이면 `44`, PROVISIONAL이면 `—`**로 갈린다. 스포일러 확인 모달은 상태와 무관하게 **`44`를 하드코딩**한다.
- **왜 문제인가:** 총 랩 수를 알 수 있는지 여부는 **아카이브 수집 완료 여부**의 문제이고(완료 세션이면 `laps.lap_number`의 최대값 = 총 랩 수), **OFFICIAL 여부는 스튜어드 확정·스포일러 게이트**의 문제다. 서로 다른 두 축을 하나로 묶었다. 그 결과 ①수집은 끝났지만 아직 결과를 안 본 사용자에게 분모가 불필요하게 `—`로 가려지고, ②수집이 92%인 상태에서도 모달만은 `44`를 흘린다.
- **API 근거:** `total_laps` 필드는 **없다**. 완료 세션에서만 `laps` 최대 랩으로 유도 가능하며, 유도 자체가 스포일러가 아니다(총 랩 수는 결과가 아니다).
- **지시:** 분모를 **수집 완료 플래그**에 연결하라 — 수집 완료면 실제 총 랩 수, 수집 중이면 `—`. OFFICIAL/PROVISIONAL과 무관하게 동일. 스포일러 모달의 분모도 같은 소스를 쓰고 하드코딩을 제거할 것.
- **수용 기준:** `Collecting 92%` 상태에서 헤더와 모달 **둘 다** 분모가 `—`이고, 수집 완료 상태에서는 PROVISIONAL·OFFICIAL 양쪽 모두 같은 총 랩 수를 보일 것.

### R41. 죽은 코드 `qBoard` 정리
- **현상:** v1 잔재인 `qBoard`(퀄리 보드)가 어디에도 바인딩되지 않은 채 남아 있고, 그 안에 **R28이 금지한 `IN LAP` 라벨**이 살아 있다. 현재 렌더되는 화면에는 나타나지 않는다.
- **지시:** 블록을 삭제하라. 살아 있는 화면에 영향이 없으니 안전하며, 남겨두면 이후 라운드에서 되살아날 위험만 있다.
- **수용 기준:** 파일 전체에서 `IN LAP` 문자열이 0건.

R35~R41 **7건 전부 반영·수용 기준 충족**을 13화면 헤드리스 렌더로 확인했다(§10 말미 검증 기록). 아래는 그 과정에서 새로 드러난 건이다. R42는 R36 수정이 부수적으로 만든 신규 결함이고, R43은 R38 수정의 잔여물, R44는 R35의 1랩 케이스 마무리, R45는 이전 라운드부터 있던 사소한 카피 누락이다.

### 10.1 데이터 의미 정합 [필수]

### R42. Practice 랩 히스토리의 "Overall best" 보라색이 개인 최고랩에 붙는다 [신규]
- **현상:** 연습 패널의 랩 히스토리에서 각 드라이버의 **자기 최고랩** 행이 보라색으로 칠해진다. 범례는 그 색을 `Overall best`(세션 전체 최고)로 정의한다. 실측: **P1 PIA**의 1:40.042(진짜 세션 최고)와 **P10 ALO**의 1:40.796(개인 최고, 세션 최고보다 0.754s 느림)이 **똑같이 보라색**이다.
- **왜 문제인가:** 20명이 각자 보라색 행을 하나씩 갖게 되므로 그 색이 아무것도 구별하지 못한다. 레이스 화면에서는 보라색이 **세션 전체 최고랩 1건**(VER 1:46.812)에만 붙어 의미가 정확했는데, 연습 화면만 의미가 어긋난다. 같은 파일 안에서 같은 색이 두 가지를 뜻하는 상태다.
- **API 근거:** `laps.lap_duration`의 **세션 전체 최소값** = overall best, **드라이버별 최소값** = personal best. 서로 다른 값이며, 범례에도 두 색이 따로 정의돼 있다(`Overall best` 보라 / `Personal best` 초록).
- **지시:** 랩 시간 색을 **세션 전체 최고랩과 일치할 때만 보라**로 하라. 드라이버의 개인 최고랩이지만 세션 최고가 아니면 **초록(`Personal best`)**을 쓸 것. 레이스 화면의 현행 동작(FL 보유자만 보라)은 이 규칙과 이미 일치하므로 건드리지 말 것.
- **수용 기준:** P10 ALO 패널에서 1:40.796 행이 **초록**, P1 PIA 패널에서 1:40.042 행이 **보라**. 즉 한 세션에서 보라 행을 가진 드라이버가 1명뿐일 것.

### 10.2 표시 규칙 [권장]

### R43. OFFICIAL에서 "핏 레인" 상태 표시가 남아 있다
- **현상:** OFFICIAL 상태의 P14 LAW 행은 인터벌 **`+0.739`(재정렬 결과로 계산된 실제 값)**을 보여주면서도, 글자색은 값이 없을 때 쓰는 **회색**이고 툴팁은 여전히 `Awaiting — car in pit lane, no interval`이다. PIT 배지는 OFFICIAL에서 이미 숨겨졌는데 색과 툴팁만 남았다.
- **왜 문제인가:** OFFICIAL은 세션이 끝나고 스튜어드 확정까지 난 상태다. **그 시점에 핏 레인에 있는 차는 존재할 수 없다.** 값이 있는데 "값 없음" 색으로 칠하고, 툴팁은 화면에 보이는 숫자를 부정한다.
- **지시:** 핏 관련 인터벌 처리(회색·`Awaiting` 툴팁·`—` 대체)는 **PROVISIONAL에서만** 적용하라. OFFICIAL에서는 모든 행의 인터벌을 일반 색으로 표시하고 툴팁을 제거할 것.
- **수용 기준:** OFFICIAL의 LAW 행 인터벌이 다른 행과 같은 색이고 마우스오버 툴팁이 없을 것.

### R44. 1랩 리타이어 케이스의 잔여 표시
- **현상:** R35의 1랩 가드 자체는 정상 동작한다(`Insufficient laps for a trend · one lap recorded`, 차트 미노출, `No pit stops · retired on lap 1`). 남은 두 곳: ①버튼이 **`Show all 1 laps`** — 문법이 틀렸고, 이미 1개 행이 다 보이므로 눌러도 아무 변화가 없다. ②스틴트 축 눈금이 **`Lap 1` · `Lap 1` · `Lap 1`** 세 번 반복된다.
- **지시:** ①총 랩 수가 기본 표시 개수(5) **이하면 토글 버튼 자체를 숨겨라**. 노출할 때의 문구는 단수/복수를 맞출 것. ②스틴트 축은 총 랩이 1이면 눈금 하나(`Lap 1`)만, 2~3랩이면 시작·끝 두 개만 표시할 것.
- **수용 기준:** 1랩 리타이어 패널에 "Show all …" 버튼이 없고, 스틴트 축에 `Lap 1`이 한 번만 나올 것.

### R45. Compare 드라이버 카드의 스톱 수 복수형 누락
- **현상:** 비교 화면 상단 드라이버 카드가 `P3 · +3.401 · 2 stop`처럼 항상 단수 `stop`으로 끝난다(2스톱 이상도 동일).
- **지시:** 스톱 수가 2 이상이면 `stops`로. 패널의 스틴트 요약(`2 stops · M13 → H9 → S6`)이 이미 올바른 처리를 하고 있으니 같은 규칙을 쓸 것.
- **수용 기준:** VER 카드가 `2 stops`, PIA·NOR 카드가 `1 stop`.

### 구현 메모 — 시안 수정 아님 (R38 관련)

R38은 시안에서 **리더갭에 페널티 초를 더해 클라이언트에서 재정렬**하는 방식으로 구현됐다. 목업으로는 정확한 결과를 내지만 **실제 구현에서 이 로직을 따라 쓰면 안 된다:**

- `/v1/session_result`의 `position`은 **이미 페널티가 반영된 공식 순위**이고, `gap_to_leader`·`points`도 확정값으로 내려온다(§8.14, 주의 15/601: "최종 순위 ≠ 마지막 `position` — 페널티 반영은 `session_result`에만"). 앱은 이 값을 **그대로 읽어야** 한다.
- 시안의 ▲/▼ 변동 표시는 `session_result.position`(공식) vs 레이스 `position`의 마지막 레코드(잠정)를 **비교해서** 만들 것. 페널티 초를 앱이 알아내 더하는 방식은 API에 페널티 시간 필드가 없으므로 애초에 불가능하다.
- `gap_to_leader`는 랩 다운 시 `"+N LAP(S)"` **문자열**이라 숫자 연산 전 타입 체크가 필요하다(주의 1).

### 11.1 데이터 의미 정합 [필수]

### R46. 같은 랩타임이 한 패널 안에서 보라·초록 두 색으로 칠해진다 (R42 미적용 잔여 3곳)

- **건드리지 말 것:** 세션 전체 값을 가리키는 보라는 이미 옳다 — 대시보드 `FASTEST LAP` 카드, 연습 화면 필드베스트 칩, 연습 `BEST SECTORS`(각 칸에 기록자 TLA 표기), 맵의 최속 링, 키모먼트 `Fastest lap`, 리더보드 `FL` 배지.

**→ 조치 불필요, 이월 목록에 기록.** 이건 dc-runtime의 템플릿 표기법 자체에서 나오는 목업 한계이지 시안 결함이 아니고, React 구현에서는 `cx={x}` 형태로 값이 확정된 뒤 DOM API로 설정되므로 **원천적으로 사라진다.** 48건을 시안에서 쫓는 것은 구현에 남지 않을 작업이다.

## 13. 9차 수정 (R47~R51) — 리플레이 트랜스포트 전역화

> 사용자 요청: **일시정지 · 재생 · 배속 · 진행바 시킹**. v8 실측 결과 **네 기능 모두 이미 구현돼 있으나 Track Map 뷰 안에만 존재**한다. 정작 리플레이의 기본 화면인 Timing 대시보드에는 트랜스포트가 없고, 그 자리의 진행바는 하드코딩된 정적 장식이다. 즉 신규 기능이 아니라 **배치와 연동의 문제**다.
>
> **v8 실측 (DOM 덤프, `#i-back15` href 기준):** map 1 / race 0 / qualifying 0 / driver 0 / compare 0. 배속 버튼(`½× 1× 2× 4× 8×`)도 map에만 1세트.
> **맵에 이미 있는 것 (유지):** 재생·일시정지 토글(`playToggle`, `setInterval` 실제 구동) · ±점프 · 배속 5단 · 진행바 클릭+**드래그** 시킹(`onScrubDown`/`onScrubMove` + window `mouseup` 해제) · 호버 시 랩/시각 툴팁(`seekTip`) · 랩 틱 · 키 모먼트 점프 · 기시청 최대 지점 음영(`maxPct`) · 경과/총시간(`1:15:21 / 1:58:30`).

### 13.1 배치·연동 [필수]

### R47. 트랜스포트가 Track Map 뷰에만 있다
- **현상:** Timing 대시보드(레이스·퀄리·연습), 드라이버 패널, Compare 어디에도 재생 컨트롤이 없다. 리플레이를 조작하려면 매번 Track Map으로 전환해야 하고, 되돌아오면 다시 조작할 수 없다.
- **지시:** 맵 하단의 트랜스포트를 **세션 셸 최하단의 상주 바로 승격**하라. `view === 'session'`이면 `mapFocus`·`sessionType`·`panelDriver`·`compareMode`와 무관하게 항상 보인다. Compare 뷰(`view:'compare'`)도 같은 세션의 리플레이이므로 포함한다.
  - 맵 뷰 안의 카드형 트랜스포트는 **제거**한다 — 한 화면에 두 개가 겹치면 안 된다. 컨트롤은 셸에 하나만 존재한다.
  - 드라이버 패널이 열려 있어도 바가 가려지지 않아야 한다(패널은 바 위쪽 영역까지만).
- **수용 기준:** Timing·Track Map·퀄리·연습·드라이버 패널·Compare 6개 상태 전부에서 재생/일시정지·배속·진행바가 조작 가능할 것. 뷰를 전환해도 재생 상태(`playing`·`playSpeed`·`replayPct`)가 유지될 것.

### R48. 대시보드 상단 진행바가 정적 하드코딩이다
- **현상:** 세션 헤더 아래 진행바는 `progressPct = '63.6%'`, `progressLabel = 'LAP 28 / —'` 문자열 상수다. 클릭·드래그 핸들러가 **0개**이고 `replayPct`를 참조하지 않는다. 맵 뷰에서는 이 정적 바와 하단 트랜스포트가 **한 화면에 동시에** 보이므로, 시킹하는 순간 위 바는 63.6%에 멈춘 채 아래 바만 움직여 **두 진행률이 어긋난다.**
- **지시:** 상단 진행바 행을 **삭제하고 하단 트랜스포트 바로 통합**하라. 진행 표시는 화면당 하나여야 한다.
  - 상단 행이 갖고 있던 정보는 하단 바로 옮긴다: 랩 카운터(`LAP 28 / 44`, 분모는 기존 `lapsDenomStr()` 그대로) · 세션 라벨(`Full race · replay`) · **VSC 존 음영(`progressZones`)은 스크럽 바 트랙 위로**.
  - 분모 툴팁(`Race distance confirmed when data collection completes`)도 함께 이관한다.
- **수용 기준:** 한 화면에 진행바가 하나뿐일 것 / 시킹 후 랩 카운터·경과 시간·존 음영이 모두 새 위치를 가리킬 것.

### R49. 시킹 후 화면이 그 시점을 반영해야 한다 (R21·R20 적용)
- **현상:** 현재 `replayPct`를 소비하는 곳은 트랜스포트 자신과 키 모먼트 필터뿐이다. 리더보드·인터벌·타이어·스틴트·Race Control은 고정 스냅샷이라 어디로 점프해도 변하지 않는다.
- **지시:** 목업에서 전 위젯을 재계산하라는 뜻이 아니다. **시킹이 화면을 바꾼다는 사실이 보이는 최소 연동**을 요구한다:
  - 랩 카운터·경과 시각·스크럽 위치 (R48로 자동 충족)
  - **키 모먼트·존 음영은 도착 지점 기준으로 재필터** — 앞으로 점프하면 도착 지점이 새 "기시청 최대 지점"이 되고(R30 ②), 그 이후 구간의 마커는 여전히 무표시(R20). 뒤로 점프해도 이미 본 구간의 마커는 남는다(`maxPlayedPct` 유지).
  - Race Control 리스트는 **커서 랩 이하 항목만** 노출(R21) — 현재 L28에서 L27·L24·L23·L22가 보이는 규칙을 커서에 연동만 하면 된다.
- **수용 기준:** L10으로 되감으면 L13 핏스톱·L23 VSC·L26 FL 마커와 해당 Race Control 항목이 사라질 것 / 다시 L28로 가면 되살아날 것.

### 13.2 컨트롤 정밀도 [권장]

### R50. ±점프 버튼의 단위가 표시되지 않고 세션마다 달라진다
- **현상:** 버튼 아이콘은 숫자 없는 원형 화살표뿐이고 툴팁도 없다. 실제 동작은 `scrubBy(±2.3)` — **퍼센트** 기반이라 레이스에서는 ±2:44(≈1랩), 퀄리·연습에서는 ±1:23으로 **같은 버튼이 세션마다 다른 양을 점프**한다. 심볼 이름만 `i-back15`/`i-fwd15`로 15초를 시사한다.
- **지시:** 점프량을 **고정 초 단위로 확정**하고 그 값을 아이콘 안 숫자 또는 툴팁으로 노출하라. 레이스 리플레이의 실사용 단위로는 **±30 s**를 권한다(15 s는 F1 리플레이에선 너무 잘다). 세션 길이와 무관하게 동일해야 한다.
- **추가:** 재생이 끝(100%)에 도달하면 현재는 ▶를 다시 눌러도 아무 일도 일어나지 않는다 — 이때 버튼을 **↺ Replay(처음으로)**로 바꿔라.
- **수용 기준:** 버튼만 보고 점프량을 알 수 있을 것 / 레이스·퀄리에서 같은 초만큼 이동할 것 / 종료 지점에서 재생 버튼이 동작할 것.

### R51. 퀄리·연습 스크럽 바에 기준선이 없다
- **현상:** 랩 틱은 `if(isRace)` 안에만 있어 퀄리·연습 바는 눈금 없는 민바다. 랩 기반 세션이 아니니 랩 틱이 맞지 않는 것은 옳지만, 대신할 기준이 없다.
- **지시:** 세션별 기준선을 넣어라 — 퀄리는 **Q1/Q2/Q3(스프린트는 SQ1~SQ3) 경계**, 연습은 **10분 간격 틱**. 퀄리 경계 틱은 커서가 지난 구간까지만 라벨을 붙인다(R20).
- **수용 기준:** 퀄리 바에서 세그먼트 경계가 식별될 것 / 미도달 세그먼트 라벨이 노출되지 않을 것.

### [선택] 키보드 단축키
- `Space` 재생/일시정지 · `←`/`→` ±점프 · `Shift+←`/`Shift+→` 이전/다음 키 모먼트. 입력 필드(허브 검색)에 포커스가 있을 때는 비활성.

### 구현 메모 — 시안 수정 아님 (R47·R49 관련)

- 트랜스포트가 순수 로컬 연산이라는 R30의 검증 결론은 그대로 유효하다(세션 전체 청크를 클라이언트가 보유, 재생 중 OpenF1 호출 0). **배속·시킹은 네트워크와 무관하다.**
- 구현에서 시킹은 타임스탬프 이진 탐색 + 소형 스트림(`position`·`stints`·`race_control`·`pit`)의 커서 시점까지 집계로 위젯 상태를 재구성한다(R21 총칙). **대시보드 위젯 전체가 이 경로를 타야 한다** — v8까지 이월돼 온 "대시보드 진행바 비연동" 항목이 R47·R48로 시안에서 해소되면, 남는 것은 이 재구성 로직뿐이다.
- 총 랩 수는 OpenF1에 `total_laps` 필드가 없다 — 완주 세션의 `max(laps.lap_number)`로만 도출된다(수집 완료 전에는 `—`). 스크럽 바의 랩 틱 개수도 같은 소스를 쓴다.

### 14.1 재생 커서 정합 [필수]

### R52. 퀄리에서 세그먼트 선택과 재생 커서가 서로를 모른다
- **증상 (실측, 퀄리 20%):** 한 화면에 **세 개의 시각**이 동시에 나온다 — 스크럽 바 playhead는 `Q1` 밴드 위 `12:00 / 1:00:00`, 헤더는 `Top 10 advance · 10:48 elapsed`, 하단 카운터와 세그먼트 컨트롤과 보드 내용은 `Q2`. 스크럽 바만 커서를 따르고 나머지는 `qseg` 상태를 따른다.
- **원인:** `counter`가 `s.qseg`를 읽는다(`isQ ? (s.qseg||'Q2') : …`). `qseg`는 세그먼트 컨트롤이 세팅하는 별개 상태이고 `replayPct`와 연결이 없다.
- **지시:** 퀄리에서 **세그먼트와 커서를 한 축으로 묶어라.**
  - Q1/Q2/Q3 버튼 클릭 = 그 세그먼트 시작 지점으로 **시킹**(R51에서 이미 쓰는 경계값 0 / 43.3 / 81.7% 재사용).
  - 커서가 세그먼트 경계를 넘으면 `qseg`도 따라 바뀐다 — 하단 카운터·보드·헤더가 모두 그 세그먼트를 가리킨다.
  - 헤더의 `NN:NN elapsed`는 트랜스포트 시계에서 파생하라(현재는 세그먼트별 하드코딩 `05:40`/`10:48`/`pole shootout`).
- **수용 기준:** 커서 20%에서 화면의 모든 세션 표기가 `Q1`을 가리킬 것 / 한 화면에 서로 다른 경과 시간이 두 개 이상 보이지 않을 것.

### R53. 퀄리·연습의 Race Control이 커서와 무연동 (R49 미적용 구간)
- **증상:** R49의 커서 필터가 `s.sessionType!=='race' || t.lap<=cursorLap` 조건이라 **레이스에만** 걸린다. 퀄리 12:00 시점 화면에 `14:53`~`14:58` 메시지 5건이 그대로 떠 있다 — 트랜스포트 시계와 아무 관계가 없다.
- **부수 문제:** 퀄리·연습의 스탬프가 `'14:'+String(30+t.lap)`, 즉 **랩 번호로 만든 가짜 시각**이다. 그래서 세션 경과 시간축과 맞출 수가 없다.
- **지시:** RC 항목에 **세션 경과 초(또는 시각)** 필드를 주고, 세션 종류와 무관하게 **커서 이하만** 노출하라. 레이스는 지금처럼 랩으로 보여도 되지만 필터는 시간축을 쓴다. 빈 상태 문구도 세션에 맞게(`No race control messages yet` 등).
- **수용 기준:** 퀄리에서 커서를 되감으면 RC 항목이 줄어들 것 / 스탬프가 트랜스포트 시계와 정렬될 것.

### 14.2 키 모먼트의 근거 [필수]

### R54. 마커·존·Race Control이 서로 다른 타임라인을 말한다
- **증상 (레이스, 실측 툴팁·본문):**

  | 소스 | 말하는 내용 |
  |---|---|
  | 키 모먼트 마커 | L23 `VSC · Stavelot` · **L24 `Green flag`** · L26 `Fastest lap` |
  | 존 음영 | `VSC · laps 23–26` |
  | Race Control 목록 | L23 `VSC deployed` · **L24 `Virtual Safety Car ending`** · **L27 `GREEN FLAG — track clear`** |

  세 소스가 재개 시점을 L24·L26·L27로 각각 다르게 말한다. 화면상으로도 **초록 점(L24)이 노란 VSC 밴드(23–26) 한가운데 박혀** "VSC 중에 그린 플래그"로 읽힌다.
- **지시:** 마커·존·RC 목록을 **하나의 이벤트 배열에서 파생**하라. 목업 값이라도 정합만 맞으면 된다 — 예: VSC L23 전개 → L25 종료(존 23–25) → L25 재개 마커, FL L26. 셋 중 하나만 고치는 방식은 금지한다.
- **수용 기준:** 재개 시점이 마커·존 끝·RC 메시지에서 동일할 것 / 재개 마커가 중립화 구간 내부에 놓이지 않을 것.

### R55. 마커 4종의 API 소스 확정 — 초록은 `GREEN`이 아니다
- **검증 (OpenF1 실 호출, 2026 스파 `session_key=11334` + 2026 8개 레이스 + 2023 싱가포르 `9165`). 상세는 `docs/openf1-api-reference.md` §8.11에 반영:**

  | 마커 | 소스 | 판정 |
  |---|---|---|
  | 🟠 핏스톱 | `/v1/pit` — `lap_number`·`date` (스파 28건, 최다 L20에 7건) | ✅ 그대로 가능 |
  | 🟣 패스티스트 랩 | `/v1/laps` 최소 `lap_duration` (스파 최속 1번 차 L44 `108.89`) | ✅ 그대로 가능 |
  | 🟡 VSC | `category='SafetyCar'`는 존재하나 **SC/VSC 구분은 `message` 텍스트뿐** | ⚠ 조건부 |
  | 🟢 그린 플래그 | **`flag='GREEN'`은 전부 랩 1의 `GREEN LIGHT - PIT EXIT OPEN`** — 레이스 중 재개를 뜻하는 GREEN은 실측 0건 | ❌ 소스 교체 필요 |

- **핵심 사실 3가지:**
  1. 재개는 **`flag='CLEAR'` + `scope='Track'`(`TRACK CLEAR`)**로 들어온다 [2023 L22·L45, 2026 L4·L18·L21]. `scope='Sector'`인 CLEAR는 섹터 해제일 뿐이라 **scope로 반드시 걸러야** 한다.
  2. SC/VSC 문구가 **시즌마다 다르다** — 2023 `VIRTUAL SAFETY CAR DEPLOYED` ↔ 2026 `VSC DEPLOYED`. 2026 8개 레이스 전체 문구는 4종뿐(`VSC DEPLOYED`/`VSC ENDING`/`SAFETY CAR DEPLOYED`/`SAFETY CAR IN THIS LAP`).
  3. **코너 이름은 API에 없다.** `Stavelot` 같은 라벨은 만들 수 없고, 있는 것은 `scope='Sector'`의 섹터 번호와 자유 텍스트 속 `TURN n`뿐이다.
- **지시 (시안 반영분):**
  - 🟢 마커 라벨을 `Green flag` → **`Restart`**(또는 `Track clear`)로. 재개를 그린 플래그라고 부르지 않는다.
  - 🟡 마커 라벨의 코너 이름 제거 — `VSC · Stavelot` → **`VSC`** (필요하면 `Sector 2`처럼 섹터 번호까지만).
  - 🟠🟣는 라벨·색 그대로 유지.
- **수용 기준:** 마커 라벨에 API로 확정할 수 없는 고유명사가 남지 않을 것.

### 14.3 신규 요청 [필수]

### R56. 드라이버 패널 랩 그래프에 SC/VSC 구간 음영
- **배경:** 중립화 구간의 랩타임은 정상 대비 **10~45% 느리다** (2026 스파 실측 — SC 랩 중앙값 159.62 s, VSC 124.33 s / 128.89 s vs 그 외 111.99 s). 지금 Lap Trend 스파크라인은 이 랩들을 아무 표시 없이 그리므로, **드라이버가 실수한 것처럼 읽힌다.** VER 패널 실측 예: L1–L4 `140.0/163.2/157.3/158.2`, L18 `122.6`, L20–L21 `130.0/121.7` — 그 사이 L19는 `111.5`로 정상이다.
- **지시:** 드라이버 패널 **Lap Trend 차트의 배경에 SC/VSC 구간을 옅은 노랑 밴드**로 칠하라.
  - 색은 스크럽 바 VSC 존과 **같은 계열**(`#D2B24E`)의 저채도 배경 — `color-mix(in srgb,#D2B24E 12%, transparent)` 권장. 선·점 위가 아니라 **뒤**에 깔린다.
  - **랩 단위로 칠한다.** 한 랩이라도 구간과 겹치면 그 랩을 칠하고, 겹치지 않는 랩은 비운다 — 위 예의 L19처럼 **중간에 끊기는 것이 정상 동작**이다.
  - 밴드에 `title` 툴팁 — `Safety car · laps 1–4` / `Virtual safety car · lap 18`. SC와 VSC는 같은 색을 쓰되 툴팁 문구로 구분한다.
  - 차트 하단 범례에 한 줄 추가 (`▨ SC / VSC`).
  - **R21 적용:** 커서 이후 구간은 칠하지 않는다. 밴드의 오른쪽 끝은 커서에서 잘린다.
- **[권장] 랩 히스토리 리스트 행**에도 같은 배경을 주면 차트와 리스트가 같은 사실을 말하게 된다. 다만 기존 행 배경(최고랩 강조 등)과 겹치지 않게 우선순위를 정할 것.
- **수용 기준:** 느린 랩이 밴드 안에 들어가고 정상 랩은 밴드 밖일 것 / 밴드가 커서를 넘지 않을 것 / 연습·예선 패널에서는 해당 구간이 없으면 밴드가 하나도 그려지지 않을 것.

### R57. 랩 히스토리의 개인 최고 랩타임이 칠해지지 않는다 (범례와 불일치)
- **증상 (실측):** 레이스 드라이버 패널의 랩 히스토리에서 **개인 최고 랩타임이 흰색(`var(--labels-primary)`)** 이다.

  | 패널 | 총 랩 | 개인 최고 | 랩타임 색 | 같은 패널의 초록 섹터 셀 |
  |---|---|---|---|---|
  | HAM | 28 | `1:47.661` | `var(--labels-primary)` | **25개** |
  | ALO | 28 | `1:49.188` | `var(--labels-primary)` | **25개** |
  | VER | 28 | `1:45.712` | `rgb(182,99,230)` 보라 (세션 최고 보유) | 25개 |

  **바로 아래 범례가 초록 = `Personal best`라고 선언**하는데 랩타임 열은 그 색을 한 번도 쓰지 않는다. 섹터 열은 개인 최고 섹터를 초록으로 칠하고 있어서, 같은 표 안에서 열마다 규칙이 다르다.
- **원인:** 랩 색 판정이 `timeColor: r.fl ? flCol : (grey ? orange : var(--labels-primary))`로 **세션 최고(`r.fl`) 아니면 무조건 기본색**이다. 개인 최고라는 분기가 아예 없다. 게다가 레이스에서는 `fl` 랩이 `tla==='VER' ? 26 : -1`로 하드코딩돼 **VER 외 전원은 `fl` 랩이 없다.**
- **지시:** 랩타임 색에 **개인 최고 분기를 추가**하라. 섹터 열이 이미 쓰는 규칙(`col()`)과 같은 의미 체계다.
  - 개인 최고 랩 → **초록 `#43C86B`**, 단 그 드라이버가 세션 최고 보유자면 → **보라 `#B663E6`**. 판정은 **R46에서 만든 `holdsOverallBest`/`bestColor`를 그대로 재사용**하면 된다(패널 단위 값이 이미 있다).
  - 나머지 랩은 현행 기본색 유지. 핏 인/아웃랩은 현행 오렌지 유지 — 개인 최고 후보에서 제외한다.
  - **행 배경은 건드리지 말 것.** 12% 배경 하이라이트는 세션 최고 행 전용 강조로 남긴다(강조가 두 개면 시끄럽다). 개인 최고는 글자색만.
  - **동률은 최초 달성 랩 하나만** 칠한다 — 현재 목업은 합성 노이즈 주기(9랩) 때문에 `1:47.661`이 3번 나온다. 실 데이터는 ms 정밀도라 동률이 사실상 없다(2026 스파 HAM 최고랩 L33 `109.454` 단일).
- **수용 기준:** HAM 패널에서 `1:47.661` **한 행만** 초록 / VER 패널은 보라 유지 / 범례의 세 색(보라·초록·노랑)이 랩타임 열에서 모두 실제로 쓰일 것.

### 구현 메모 — 시안 수정 아님 (R54·R55·R56·R57 관련)

- 스크럽 바 마커 위치는 **`lap_number`가 아니라 `date`**로 잡아라. 2026 스파 L18에서 `VSC DEPLOYED`와 `VSC ENDING`이 같은 랩에 찍혔다 — 랩 단위로 배치하면 두 이벤트가 겹친다.
- 중립화 **구간(존)**은 `SafetyCar` 전개 이벤트 ~ 그 다음 `flag='CLEAR' scope='Track'`의 `date` 쌍으로 만든다. 전개만 있고 해제가 없으면(세션 종료 등) 커서까지로 자른다.
  - **`… IN THIS LAP` / `… ENDING`은 해제 예고이지 재개가 아니다** — 2026 스파 실측으로 `TRACK CLEAR`보다 각각 78초·13초·14초 앞선다. 구간 끝으로 쓰면 존이 짧아지고 재개 마커가 어긋난다(= R54가 지적한 모순의 구조적 원인).
  - 실측 구간: SC `13:05:25~13:13:50`(8분 25초), VSC `13:39:13~13:39:59`(46초), VSC `13:43:18~13:45:06`(1분 48초). 교차검증 — 해당 구간 랩타임 중앙값 159.62 s / 124.33 s / 128.89 s vs 나머지 791랩 111.99 s.
- **세션 통째로 데이터가 없는 경우가 있다.** 2026 개최 완료 13개 레이스 중 2개(Bahrain·Saudi Arabia)가 `race_control`·`pit`·`laps` 전부 404다. 리플레이 대상 목록은 일정이 아니라 **실제 적재 여부**로 만들고, 마커 레이어는 소스가 없으면 조용히 비는 형태로 설계할 것.
- **개인 최고랩 플래그는 API에 없다 — 계산은 `min()` 한 번이다.** `/v1/laps`에 `is_personal_best` 류 필드가 없으니 드라이버별 `min(lap_duration)`을 직접 구하고 `is_pit_out_lap`을 제외한다. 미니섹터의 `2049`(개인 베스트)는 섹터 단위 플래그이지 랩 단위가 아니다 — R57을 그 코드로 대신할 수 없다. 실행 결과(2026 스파, 입력 875행 → 출력 21행): 세션 최고 NOR `108.890` @L44, 그 외 20명은 각자 개인 최고. **난이도 이슈가 아니라 시안이 이 값을 안 칠하고 있다는 것이 R57의 요지다.**
- **단, 색은 커서에 따라 바뀐다 (R21).** 개인 최고와 세션 최고 모두 **커서 시점까지의 러닝 min**이어야 한다. 2026 스파 실측 — 보라를 받는 사람이 `L10 HAM(110.199)` → `L20 VER(110.031)` → `L28 ANT(109.333)` → `L41 NOR(108.927)` → `L44 NOR(108.890)`로 옮겨가고, HAM 자신의 개인 최고도 `110.199@L9` → `109.515@L23` → `109.454@L33`로 갱신된다. **최종 결과값을 미리 박아 두면 리플레이 중 미래 정보를 노출하는 셈이다.** 수집 단계에서 랩별 러닝 min을 미리 접어 두면 재생 중 연산은 조회 한 번으로 끝난다.
- **SC/VSC 구간 도출은 LLM도 정규식도 필요 없다.** `race_control`을 `date` 순으로 훑는 상태 기계 하나면 된다 — 여는 조건 `category='SafetyCar' && message.endsWith('DEPLOYED')`, 닫는 조건 `flag='CLEAR' && scope='Track'`, 종류는 `message`가 `VSC`/`VIRTUAL`로 시작하는지. 2023~2026 레이스 81개 전수에서 `SafetyCar` 문구는 **7종뿐**이라 사실상 열거형이다. 단 두 가지 처리가 필요하다 — `VSC DEPLOYED` 직후 `SAFETY CAR DEPLOYED`가 오는 **격상**(2024 Qatar 실측, 20초 간격)과, 알려지지 않은 문구가 나올 때의 로깅. 코드와 검증 결과는 `docs/openf1-api-reference.md` §8.11.
- `/v1/race_control`의 `category`에 `SafetyCar`가 있다는 사실은 공식 문서 예시에 없어 우리 레퍼런스도 누락하고 있었다 — 2026-07-27 실측으로 §8.11에 추가했다.

### 15.1 커서 이후 정보 노출 — R21 총칙 위반 [필수]

### R58. 드라이버 패널이 커서를 전혀 모른다 (R56이 드러낸 비대칭)
- **증상 (실측, 커서 45.5% = L20):** 트랜스포트는 정확히 잘린다 — 마커 `L13` 1개, 존 0개, RC `LAP 13` 1건. 그런데 같은 화면에서 VER 패널을 열면:
  - 랩 히스토리 행이 **29개** 그대로(L21~L28 + 진행 중 L29), 그중 **L26 `1:45.712`가 보라색**
  - `Lap Trend`의 `BEST`도 **`1:45.712` 보라** — 레이스 최대의 스포일러(패스티스트 랩)가 커서보다 **6랩 뒤** 값이다
  - 커서 L28에서 렌더한 결과와 랩 행·색·스탯이 **바이트 단위로 동일**하다(HAM 패널 비교)
- **같은 카드 안의 모순:** 밴드는 `neutralLaps()`로 커서에서 잘려 **0개**가 되고 범례도 사라지는데, 랩 행 23~25의 **노란 배경은 `r.neutral`(커서 무제한)이라 그대로 남는다.** 커서 L20에서 "노란 행은 있는데 밴드도 범례도 없다". R56의 클리핑이 옳고 나머지가 안 따라온 상태다.
- **번져 있는 곳:** 리더보드 VER 행의 `FL` 배지와 대시보드 `FASTEST LAP` 카드 `1:46.812`도 커서 L20에서 그대로 보인다. RC와 마커는 이 사실을 숨기는데 카드 세 곳이 말해 준다.
- **원인:** `genLaps`의 `total = cfg.total || retireLap(tla) || 28` — 커서와 무관한 고정값. 진행 중 행도 `inProg={lap:29,…}` 하드코딩.
- **지시:** 패널의 랩 수를 **커서 랩에서 파생**하라.
  - `cursorLap`(트랜스포트가 이미 계산하는 값)을 단일 소스로: `total = min(cursorLap, retireLap || cursorLap)`, 진행 중 행은 `cursorLap + 1`.
  - 그러면 스탯(`Best Lap`·`Last`·`Avg`)·`Lap Trend`·스파크라인·스틴트 축·`Show all N laps`·밴드·행 배경이 **한 소스로 정합**하고, R57의 개인 최고도 자동으로 커서 시점 러닝 min이 된다.
  - `FL` 배지와 `FASTEST LAP` 카드도 커서 이하에서 나온 최고랩으로 판정하라(커서 L20이면 L20까지의 최속, 아직 없으면 `—`).
- **수용 기준:** 커서 45.5%(L20)에서 — VER 패널 랩 행 **20개 이하**, `1:45.712` 미노출, `BEST`가 L20까지의 최소값, 밴드 0개일 때 노란 행도 0개(둘이 항상 일치), `FASTEST LAP` 카드가 `1:46.812`가 아닐 것.

### R59. 퀄리 보드가 커서를 모른다 (R52가 드러낸 지점)
- **증상 (실측, 퀄리 0%):** 헤더는 `0:00 elapsed`, RC는 `No race control messages yet — 0:00 elapsed.`인데 **Q1 보드에는 21명 전원의 최종 베스트가 다 찍혀 있다** — `1:40.767`, `1:40.786`, `1:40.888`, `1:40.899`, `1:40.992` …. 필드베스트 칩도 완성값이다.
- **왜 지금 문제인가:** R31에서 **미래 세그먼트**는 `—`로 게이팅했지만 현재 세그먼트 **내부**는 손대지 않았다. 세그먼트가 수동 토글이던 v9까지는 시계가 장식이라 이 모순이 안 보였는데, R52가 시계를 커서에 묶은 순간 "0:00 경과인데 Q1 결과가 완성돼 있다"가 드러났다.
- **지시:** 세그먼트 **내부**도 커서 기준으로 게이팅하라. 목업이므로 정밀한 개별 랩 타임축까지는 필요 없고, **세그먼트 경과 비율에 따라 타임이 채워지는** 형태면 충분하다 — 예: 경과 0~20%는 전원 `—`, 이후 순차적으로 채워지고 세그먼트 종료 시점에 전원 확정. 필드베스트 칩·KO 존·포커스 카드·미니섹터가 모두 같은 소스를 쓸 것.
- **수용 기준:** 0%에서 타임 셀이 전부 `—`이고 필드베스트도 `—` / 30%(Q1 종료)에서 21명 확정 + KO 6명 표시 / 어느 시점에서도 "경과 0:00인데 결과 완성" 상태가 없을 것.

### 15.2 R52의 부수 효과 [필수]

### R60. 세그먼트 탭이 세그먼트 **시작**으로 점프해 빈 화면을 보여준다
- **증상:** `setQSeg`가 `_setPct(qSegStartPct(sg))`이라 `Q1` 탭 = 0%로 이동한다. 실측 0% 화면은 `0:00 elapsed` · RC 0건 · KO `No eliminations yet` — **아무 일도 안 일어난 세션**이다. R59를 고치면 타임까지 전부 `—`가 되어 "탭이 고장 났다"로 읽힌다. v9까지는 `Q1` 탭이 Q1 최종 결과를 보여줬으니 사용성 회귀다.
- **지시:** 탭 클릭 시 목표 지점을 **`clamp(maxPlayedPct, segStart, segEnd)`**로 잡아라.
  - 이미 본 세그먼트(예: 90%에서 `Q1` 클릭) → `segEnd`(30%) = 그 세그먼트의 **결과** 화면
  - 아직 안 본 세그먼트(예: 20%에서 `Q3` 클릭) → `segStart`(81.7%) = 시작 지점, 앞질러 결과를 보여주지 않음(R20)
- **수용 기준:** 커서 90%에서 `Q1` 클릭 → 커서 30%·`Top 15 advance`·KO 6명 표시 / 커서 20%에서 `Q3` 클릭 → 커서 81.7%이고 Q3 결과는 아직 비어 있을 것.

### 15.3 값 정합 [권장]

### R61. 패스티스트 랩 값이 세 곳에서 다르다
- **실측:** VER 패널 랩 히스토리 L26 = **`1:45.712`**(보라) / 대시보드 `FASTEST LAP` 카드 = **`1:46.812`** / RC 메시지 = `… 1:46.812` / 리더보드 VER `LAST LAP` = `1:46.812`. 같은 랩을 가리키는 네 표시 중 패널만 1.1초 빠르다.
- **원인:** `genLaps`의 `flSec` 기본값이 `seedSec - 1.1`이다. `seedSec`가 리더보드 마지막 랩(`1:46.812`)이라 패널은 항상 그보다 1.1초 빠른 값을 만든다. (v7 이전부터 있던 값이지만 R57이 이 랩을 색의 기준점으로 쓰면서 눈에 걸린다.)
- **지시:** 세션 최고 보유자는 `flSec`에 **선언된 패스티스트 랩 값**(`fastest.time`)을 주입하라. 소스는 하나(`fastest`)여야 한다.
- **수용 기준:** VER 패널 L26 = `1:45.712`가 아니라 `1:46.812`.

### R62. RC 패스티스트 랩 메시지의 차량 번호가 다른 드라이버다
- **실측:** `Fastest lap of the race — car 1, 1:46.812.` 그런데 이 로스터에서 **car 1 = NOR**이고 패스티스트 랩 보유자는 **VER = car 3**이다(`FL` 배지·`FASTEST LAP` 카드·마커 전부 VER).
- **지시:** `car 1` → **`car 3`**. (같은 배열의 `car 43` = COL은 맞다.)
- **수용 기준:** RC 메시지의 차량 번호가 `FASTEST LAP` 카드의 드라이버와 일치.

### 구현 메모 — 시안 수정 아님 (R58·R59 관련)

- **R58은 구현에서는 오히려 단순하다.** 리플레이가 세션 청크를 클라이언트에 다 들고 있으니 "커서 랩 이하로 자른 랩 배열"이 곧 뷰 모델이다. 문제는 **자르지 않은 뷰 모델을 시안이 정답처럼 보여주고 있다**는 점 — 그대로 옮기면 리플레이 내내 결과를 노출한다.
- **패스티스트 랩·개인 최고는 커서별 러닝 min으로 접어 둘 것.** 수집 단계에서 랩별로 (세션 최고, 드라이버별 최고)를 미리 계산해 두면 재생 중 연산은 조회 한 번이다. 실측 근거는 §14 구현 메모(2026 스파에서 보유자가 HAM→VER→ANT→NOR로 4회 이동).
- **R56의 다중 구간·불연속 케이스는 목업에서 검증 불가.** 목업의 중립화 구간이 하나(L23~25)뿐이라 "밴드가 중간에 끊긴다"는 코드로만 확인했다(연속 랩만 하나의 rect로 병합). 실제 데이터는 구간이 여럿이다 — 2024 Qatar 실측 `SC L1–4` / `SC L35–39` / `SC L40–42`. 구현 후 이 세션으로 밴드 3개·불연속 렌더를 확인할 것.
- **밴드 툴팁은 dc 런타임에서 표시되지 않을 수 있다.** `<title>{{ bd.title }}</title>`이 `<title><span class="sc-interp">…</span></title>`로 렌더된다(dc-runtime이 보간 텍스트를 span으로 감싼다). SVG `<title>`은 텍스트 노드만 툴팁으로 쓰므로 목업에서는 빈 툴팁이 될 수 있다. **React 구현에서는 순수 텍스트가 되므로 소멸** — §12 콘솔 경고와 같은 성격의 목업 한계이니 시안에서 고칠 것은 없다.

### 16.1 커서 이후 정보 노출 잔여 [필수]

### R63. 리더보드와 패널의 `LAST`가 커서를 무시한다 (R58 잔여 2곳)
- **증상 (실측, 커서 45.5% = L20):** 패널·마커·RC·`FASTEST LAP` 카드·`FL` 배지는 전부 정확히 잘렸는데, **패스티스트 랩 시간 `1:46.812`가 두 곳에 그대로 남아 있다.**
  - 리더보드 VER 행 `LAST LAP` 열 = `1:46.812` **보라**
  - 드라이버 패널 `LAST` 스탯 카드 = `1:46.812` **보라**
  - 같은 패널의 랩 히스토리는 마지막 완료 랩 L20 = `1:46.612`라 **한 카드 안에서 `LAST`가 두 값**이다.
- **원인:** 두 곳 다 정적 `raceRows()`의 `row[3]`을 그대로 쓰고, 색은 `r[0]==='VER' ? '#B663E6'` / `t==='VER' ? SCc.p` 하드코딩이다. R58에서 `flSeen()`으로 게이팅한 목록에 이 둘이 빠졌다.
- **지시:** `LAST`를 **커서 시점의 마지막 완료 랩**에서 파생하라(패널은 이미 그 값을 갖고 있다 — 랩 히스토리 맨 위의 완료 행). 보라색은 `flSeen()`이고 그 드라이버가 세션 최고 보유자일 때만.
- **수용 기준:** 커서 45.5%에서 화면 어디에도 `1:46.812`가 없을 것(랩 4의 우연한 동일값 제외) / 패널 `LAST`와 랩 히스토리 최상단 완료 랩이 항상 같은 값일 것.

### 16.2 패스티스트 랩 값 정합 잔여 [필수]

### R64. 세션 최고 보유자의 랩타임이 선언된 패스티스트 랩보다 빠르다 (R61 잔여)
- **증상:** R61로 VER 패널 L26이 `1:46.812`가 됐는데, **같은 표에 그보다 빠른 랩이 4종(`1:46.412`·`1:46.512`·`1:46.612`·`1:46.712`) 있다.** 결과가 세 가지로 어긋난다:
  1. 한 패널에 **보라가 2행** — L26(세션 최고)과 L9(개인 최고 `1:46.412`, `bestColor`가 보라라서). R42·R46이 없앤 바로 그 상태다.
  2. 패널 `Lap Trend`의 `BEST`가 `1:46.412`인데 대시보드 `FASTEST LAP` 카드는 `1:46.812` — 여전히 두 값.
  3. **Compare 뷰와 스파크라인은 아직 `1:45.712`다.** R61이 `panelVals`의 호출부에만 들어가서, `genLaps(t)`를 인자 없이 부르는 나머지 3개 경로(Compare 카드 `best`, Compare 차트 축, `trendFor`)는 옛 값을 그대로 만든다. Compare 카드 VER `BEST` = `1:45.712` 실측.
- **지시:** 보정을 **`genLaps` 안으로** 옮겨라. 그 드라이버가 세션 최고 보유자면(`tla === FASTEST().tla`, 레이스 세션) ① `flSec = lapSec(FASTEST().time)`을 쓰고 ② **나머지 랩은 `flSec`보다 빠를 수 없게 하한을 걸어라**(예: `t = max(t, flSec + 0.05)`). 그러면 호출자 4곳이 자동으로 같은 값을 쓴다.
- **수용 기준:** VER 패널에 보라가 **1행(L26)**뿐일 것 / 패널 `BEST`·`FASTEST LAP` 카드·Compare 카드 `BEST`·RC 메시지가 모두 `1:46.812`일 것 / 화면 어디에도 `1:45.712`가 없을 것.

### 16.3 퀄리 게이팅 잔여 [권장]

### R65. 기록 없는 드라이버가 최종 순위대로 정렬되고 순번까지 붙는다 (R59 잔여)
- **증상:** 퀄리 0% — 타임은 전부 `—`인데 보드는 `P1 PIA · P2 VER · P3 NOR · P4 HAM …`으로 **최종 Q1 순서 그대로** 서 있고 순번도 1~20이 찍혀 있다. 아직 아무도 안 달렸는데 결과 순서가 보인다. Q3에서 `Q3` 탭으로 점프한 직후(타임 0개)도 마찬가지로 `P1 PIA`부터다.
- **원인:** `qBoardOrder`가 `확정 그룹 + 미확정 그룹`을 잇는데, 미확정 그룹의 내부 순서가 최종 순위(`qPools().order`)다.
- **지시:** 기록 없는 드라이버는 **중립 기준**으로 정렬하고(카 넘버 오름차순 권장) **순번 칸은 `—`**로 두라. 확정된 드라이버만 1위부터 번호를 받는다.
- **수용 기준:** 퀄리 0%에서 P 열이 전부 `—`이고 행 순서가 최종 순위와 다를 것 / Q1 50%에서 상위 8행만 번호가 있고 나머지는 `—`일 것.

### 구현 메모 — 시안 수정 아님

- **R63의 `LAST`는 구현에서 정의가 다르다.** 목업은 `LAST`를 정적 문자열로 갖고 있지만, 실제로는 `/v1/laps`에서 **커서 시각 이전에 끝난 마지막 랩**이다. 랩 종료 시각(`date_start + lap_duration`)으로 판정해야 하며, 핏 인/아웃랩도 그대로 `LAST`가 될 수 있다(빠른 랩만 고르는 게 아니다).
- **R64의 "선언값과 생성값" 문제는 목업 고유다.** 실제 구현에서는 패스티스트 랩이 랩 데이터에서 파생되므로(`min(lap_duration)`) 정의상 그 드라이버의 최고랩과 같다. 다만 **커서별 러닝 min을 쓰는지**는 여전히 확인 대상 — §14 구현 메모 참조.
- **R59가 만든 "느린 주자부터 확정" 규칙은 목업용 근사다.** 실제로는 각 드라이버의 랩 종료 시각이 데이터에 있으니 근사가 필요 없다 — 커서 이전에 끝난 랩 중 최소값이 그 시점의 베스트고, 하나도 없으면 `—`다. 시안의 규칙은 "보드가 점차 채워진다"는 **표시 규칙**만 확정하는 용도로 읽을 것.

## 17. 전수 감사 — API·스택 적합성 최종 확인 (2026-07-28)

> **왜 후속이 계속 나왔는가에 대한 답이기도 하다.** 지금까지의 감사는 "직전 라운드의 수용 기준 + 그 수정이 새로 노출한 표면"만 봤다 — R47이 트랜스포트를 전 화면에 올리자 커서 비연동(R52·R53)이 보였고, R52가 시계를 커서에 묶자 보드 게이팅 부재(R59)가 보이는 식으로, 수정이 다음 결함을 노출하는 연쇄였다. 이 절은 그 방식을 버리고 **시안의 모든 표시 요소를 ① OpenF1 API로 만들 수 있는가([openf1-api-reference.md](./openf1-api-reference.md)) ② 확정 스택(리플레이 전용·R2 청크·클라이언트 계산, [infra-architecture.md](./infra-architecture.md))에서 돌아가는가 ③ 커서 규칙(R21)을 지키는가** 세 축으로 한 번에 훑은 결과다. **결론: 시안에 남은 결함은 R63~R65 3건이 전부이고, 이후 신규 라운드는 없다.**

### 17.1 요소별 적합성 매트릭스

### 17.2 시안 결함으로 남은 것 = §16 R63~R65가 전부

이 매트릭스 기준으로 v11을 다시 훑은 결과, **커서 규칙 위반·값 불일치로 남은 것은 R63(LAST 2곳)·R64(선언값보다 빠른 랩 4종)·R65(미기록자 순번) 3건뿐이다.** 그 외 후보는 전부 아래 중 하나로 종결:

- **리더보드 순서·인터벌·타이어 에이지가 커서에 정적** — R49에서 **명시적으로 목업 범위 밖으로 확정**한 항목("전 위젯 재계산까지는 목업에서 안 해도 된다"). 구현에서는 `position`/`intervals` 커서 집계로 자연 해결되며, 스포일러급 신호(FL·패스티스트 랩 시간)만 R58·R63으로 막았다. **신규 라운드 사유 아님.**
- **퀄리 고정 경계(43.3/68.3%)·"느린 주자부터" 게이팅** — 목업 근사로 허용. 구현은 실데이터 경계(위 매트릭스)를 쓰므로 근사의 정밀도는 무의미. **시안 수정 불요.**
- **맵의 On track/Out lap/In pit 상태** — 구현은 `laps` 진행 상태 + `location`으로 근사. 시안 표시 규칙만 확정하면 됨. **수정 불요.**
- **`Rain expected …` 티커 문구** — RC는 원문 표시용이므로 구현은 실제 메시지를 그대로 보여준다. 예시 문구일 뿐. **수정 불요.**

### 17.3 구현 측 조치 2건 (시안 무관 — 수집기/앱 백로그)

1. **트랙 지오메트리 캐시:** MultiViewer API는 OpenF1보다도 보장이 없는 서드파티다. 수집기가 백필 시 `circuit_info_url` JSON을 함께 받아 `replay/{year}/{meeting_key}/circuit.json.gz`로 R2에 저장할 것 — 시청 경로를 외부 API에서 분리하는 infra §1의 원칙과 동일.
2. **국적 매핑:** `drivers.country_code`가 2026부터 null(§8.3, 시즌 후 필드 제거 예정) — 앱에 `driver_number→국가` 정적 테이블을 두고 시즌별로 관리.

### 17.4 종결 선언

- **결함 지시는 11차(R63~R65)가 마지막이다.** 반영본(v12) 검증은 수용 기준 + 회귀 확인만 수행하고, **결함 신규 항목은 발행하지 않는다** (회귀 제외).
- 이후 발견되는 것은 시안이 아니라 **구현 백로그**(17.3 및 각 절 "구현 메모")로 적재한다.

### 17.5 11차는 별도 파일로 분리 — [design-brief-11.md](./design-brief-11.md) [2026-07-28]

이 파일이 너무 길어져 Claude Design에 통째로 붙이기 어렵다. **11차 지시는 자기완결적인 새 파일**로 옮겼고, 사용자 요청 신규 기능 2건이 추가됐다:

**R66·R67의 실측 근거는 전부 [openf1-api-reference.md](./openf1-api-reference.md)에 반영했다** — §6.2.1(MultiViewer 스키마·좌표계 일치), §8.4(미니섹터 개수·경계 검증·갭 정확도), §8.9(`car_data.drs` 시즌별 가용성). 저장 설계는 [infra-architecture.md](./infra-architecture.md) §3.4(서킷 지오메트리 정적 자산).

**SLM 판정 정정 [2026-07-28 재조사].** 처음에 "제외"로 답한 것은 **오버테이크 모드(에너지 배분)와 스트레이트 모드(액티브 에어로)를 뭉갠 오판**이었다. 재조사 결과:
- **스트레이트 모드는 FIA가 서킷마다 지정한 액티베이션 존에서만 쓴다** — 근접 조건 없이 전 드라이버 사용 가능. 멜버른 5곳·스파 5곳 공표. **구역이 실재한다.**
- 다만 좌표를 주는 API·데이터셋은 없다 → `data/slm-zones.json` 수동 큐레이션 (이 프로젝트 `origin/personal_page` 브랜치의 옛 계획 §1.3.5도 같은 결론이었다).
- 오버테이크 모드는 DRS처럼 **디텍션 1 + 액티베이션 1** 구조다.
- **`race_control`에 `OVERTAKE ENABLED`/`OVERTAKE DISABLED`가 있다** [실측: 2026 완료 레이스 13개 중 11개, 문구 2종뿐]. 2023의 `category='Drs'` + `DRS ENABLED/DISABLED`를 대체하는 신호다. 차량별 사용 여부는 여전히 없다.

**기존 자산 재사용:** `origin/personal_page` 브랜치에 `public/trackOutlines/{circuit_key}-{year}.json` **166개**와 DRS zone 도출 스크립트(`scripts/_lib/drsZonesDeriver.ts`, 결과 `drsZones_2-{2023,2024}.json`)가 이미 있다. 다만 그 브랜치의 아웃라인 소스는 julesr0y SVG라 affine 변환이 필요했고, MultiViewer로 바꾸면 그 단계와 함께 미니섹터·마셜 섹터·코너 메타데이터까지 공짜로 얻는다 (infra §3.4·§9).
